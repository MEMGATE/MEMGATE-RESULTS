# RP-2 spec: does a fact learned in the weights carry to the questions that follow from it?

**Status:** spec, 21 October 2026, 13:00 IST. Written before any RP-2 question is asked.
**Companion:** [RP-1](RP1-SPEC-2026-10-21.md) asks the same questions with the new fact in a verified memory. RP-2 asks them of models that learned the fact by fine-tuning.

## Why
RP-1's dev run showed that one verified sentence in memory carries a new office holder to the reverse question ("X holds which position?") and to "is the previous holder still in office?". Facts learned by fine-tuning are known to carry poorly in the reverse direction. RP-2 measures how far facts that GPT-4.1 learned through Azure's hosted fine-tuning carry, on the same questions. Together the two tests show what each route of continual learning gives, and so where a verified memory should sit beside the weights.

## Design
**Models:** no training and no new deployment.
- **NAIVE-12:** FT-2 main world 8202's NAIVE model after session 12 (`rt1-8202-naive-12`), trained on every report.
- **ENGINE-12:** the same world's ENGINE model after session 12 (`rt1-8202-engine-12`), trained on what the gate admitted.
- **FROZEN:** the untouched `gpt-4.1-base` on memgate-ft-ncus.

RT-1 kept the two fine-tuned deployments on memgate-ft-eus2b. The developer tier deletes them about 24 hours after creation (about 10:30 on 22 October), so RP-2 must finish before then.

**Offices:** RP-1's offices (TM-1 world 8000's pool, in its fixed order), keeping only those that world 8202 did not attack and whose final holder in world 8202 is RP-1's current holder:
- **dev:** 24 of RP-1's 50 dev offices;
- **main:** 150 of RP-1's 300 main offices.

**Questions:** RP-1's four kinds with no memory (DIRECT, REVERSE, PREVIOUS, STILL), with RP-1's instructions. The system message carries FT-2's session-12 date: "Today is 2026-10-18. …". DIRECT is then asked exactly as the models were trained, and the other three kinds are phrasings no job trained on.

**Calls and scoring:**
- Temperature 0, at most 150 tokens, as RT-1.
- Scoring is RP-1's `correct()`.
- The fine-tuned models are asked directly. In FT-2 the ENGINE arm routes questions by the scope rule, which sends a question that names no learned office (REVERSE names a person) to the untouched model. That is reported as a consequence of the design, not measured separately.

## Measures and hypotheses (to be fixed after dev)
**The statistic:**
- For a fine-tuned arm A and a question kind X: gain_X = A − FROZEN on X (0/1 per office).
- The carry deficit on X is gain_DIRECT − gain_X. It is near 0 if what training added to DIRECT also reaches X, and large if it does not.

**Hypotheses:**
- H1 (REVERSE), H2 (PREVIOUS) and H3 (STILL): the carry deficit, averaged over NAIVE-12 and ENGINE-12 per office.
- Each has a 95% bootstrap interval over offices (10,000 resamples, seed 12345).
- **WIN** if the interval lies wholly above +1 pp and both arms' own estimates are above 0.

**Descriptive:**
- each arm's accuracy per kind;
- carry rates, P(X right | DIRECT right);
- the same ripple gaps for gpt-4.1-base given the verified memory in RP-1, on the same offices.

## Limits
- **Scale:** one FT-2 world, so one pair of fine-tuned models; 150 offices.
- **Different conditions across routes:** RP-1 and RP-2 differ in date and run, so the route comparison is descriptive.
- **Facts only.** The knowledge involved is simple.
