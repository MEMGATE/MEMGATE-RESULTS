# Vision: the Saṃskāra Engine, an AI that learns on the job into its own weights, safely

18 October 2026. This is a target and a research programme, not a result. Every step is to be preregistered and tested in this lab's way.

## 1. What no one has yet

Today's assistants are frozen after training. Their "memory" is retrieval into the context window. What they learn on the job does not become part of them.

Research is moving to weight-level learning from experience:
- **SEAL (MIT, NeurIPS 2025):** the model writes its own training edits and updates its weights. Its authors name the open problems: catastrophic forgetting under repeated edits, a cost of tens of seconds per edit, and the need for an explicit task for each context.
- **Titans and Nested Learning (Google):** memory that learns at test time, built into the architecture.

Commentary in 2026 calls continual learning the next frontier. It names the same risks: drift, poisoning and privacy. No frontier lab has reported shipping weight-level continual learning in a production model.

## 2. What next-level continual learning should be

It should learn like a good employee, measured on all of these together:

| # | Property | How it is measured | Sanatana source |
| --- | --- | --- | --- |
| 1 | **Learns from one correction.** Told once, it does not repeat the mistake. | errors repeated after a correction | jijñāsā; Vṛtti–Saṃskāra |
| 2 | **Never forgets what matters,** and changes what has changed. | old-skill accuracy after many updates; update accuracy | bādha and apavāda: the new sublates the old without erasing it |
| 3 | **Knows where every belief came from,** and can unlearn on request. | provenance completeness; residual recall after unlearning | the Nyāya-Pramāṇa evidence graph |
| 4 | **Cannot be poisoned, and does not absorb its own errors.** | attack success; wrong-lesson rate | Arthaśāstra 1.12 corroboration; the vṛtti filter; YS 1.50 (the impression born of true insight blocks other impressions) |
| 5 | **Applies a lesson only where it holds;** transfers only after checking. | cross-context contamination; transfer gain | Kiraṇa locus; Indra's Net |
| 6 | **Knows what it does not know,** after every update. | calibration and abstention before and after updates | kṣetrajña (Gītā 13); ML-7 |
| 7 | **Consolidates while idle, and checks its own constitution before accepting any change.** | regression on a fixed core test suite; rollbacks | saṃskāra formation in "sleep"; prakṛti–vikṛti |

## 3. The engine

1. **Experience (vṛtti).** Every task, outcome and correction enters the evidence graph with its pramāṇa:
   - pratyakṣa: verified by the environment;
   - anumāna: inferred;
   - śabda: told by a user, a document or an agent;
   - upamāna: by analogy.
2. **Admission.** Only grounded items become candidate lessons.
   - Testimony never overrides verified observation.
   - Independent corroboration is needed before trust.
   - Sources that frequently differ lose credence (AR-1, MX-13).
3. **Context memory (Level 1).** Admitted lessons, scoped to their locus, are used at once, with abstention where none applies.
4. **Consolidation into weights (Level 2, the saṃskāra step).** Lessons confirmed again in later use (SK-1's R = 3) are distilled while idle into small adapters, one per locus.
   - **Constitution check.** Before an adapter is accepted, it must pass the fixed core suite (prakṛti) and show no regression on earlier lessons (vikṛti check). Otherwise it is rolled back.
5. **Sublation and unlearning.** A lesson that is later refuted is kept with its record and blocked. On request, every adapter trained on it is retrained without it, which the evidence graph makes traceable.

## 4. How it would be proven

**An "on-the-job" benchmark, built from public task streams.** Examples: text-to-SQL over fixed databases, diagnosis, coding with tests, policy-following service tasks. An agent works through weeks of simulated tasks with corrections, planted poison and changed facts. The measures are its improvement curve and properties 1–7.

| Comparison | |
| --- | --- |
| Baselines | the same base model frozen; plain retrieval memory; self-curated memory (Dynamic Cheatsheet style); naive fine-tuning on all experience (SEAL style, no gating) |
| Target headline | a lasting improvement curve with near-zero forgetting, poisoning cut by most of its success, and full provenance and unlearning, all at once |

## 5. Levels, needs and honest risks

| Level | What it needs | Rough time |
| --- | --- | --- |
| 1. Pramāṇa Memory, in context (CL-1 to CL-4 in [the plan](CL-PLAN-2026-10-18.md)) | API model access (keys in environment variables) | weeks |
| 2. Saṃskāra consolidation into adapters | GPU machines and an open-weight model (7B–20B), with standard ML libraries. This project leaves the lab's standard-library-only rule; that will be stated. | months |
| 3. The on-the-job benchmark | public data only; can start now | weeks |

**Risks:**
- Strong teams (Google, MIT and the labs themselves) work on this. The opening here is the *safe and verifiable* side (properties 3, 4 and 7), which the capability-first work leaves open.
- Weight updates may forget despite the gates.
- Every claim needs the same preregistered discipline as the 54 tests so far.
