# NB-1 preregistration: naive fine-tuning with a small learning rate, against the learner (7B) (frozen)

**Status: FROZEN on 27 October 2026, 21:03 IST, before any NB-1 world was packed or run.** This covers Gemini's blind spot that plain sequential fine-tuning with a small learning rate is a strong baseline for language models (much of what looks like forgetting is spurious). It falls under item 2 of the package's fixed list (Gemini's points), and was added at the founder's request at 20:55 IST.

## The arms
NAIVE as in CCL-4 (every report and recipe that arrives, fine-tuned session by session, LoRA on the attention projections, two epochs), with the learning rate lowered from CCL-4's 2e-4 to:
- **2e-5** (ten times smaller);
- **5e-6** (the rate Gemini cites for plain sequential fine-tuning).

Each is run on CCL-4's main worlds 9702 and 9703 with CCL-4's frozen GPU runner in Colab's layout (`colab_pack.colab_kernel("7b", 4)`, `a5567bf0…`). The packer changes only the learning rate in the payload, and checks that every question equals CCL-4's payloads.

Code SHA-256 (NB-1 packer and analysis, `nb1.code_hash()`): Code SHA-256: `0080957b7aa35cded80f43f050419bd4059b4891977f690dae73a24fc1195182`

Analysis: `cl/nb1.py report`. It uses CCL-4's scoring (`ccl2.measures`), CCL-4's frozen `cl/ccl4.py` (`525e21ff010b…`) for the kept offices, and `ccl1.boot`. It was checked end to end on mock outputs.

## Design
- **Packs.** `PYTHONHASHSEED=0 python cl/nb1.py pack 970X:main runs/nb1-main-7b/w970X-lr2e-5 --lr 2e-5 --questions-from runs/ccl4-main-7b-colab/w970X/dataset/payload.json --prereg docs/NB1-PREREG-2026-10-27.md`. The same command with `--lr 5e-6` writes into `w970X-lr5e-6`.
- **Machine.** Azure's serverless A100 (`cl/aca_run.py`).
- **Comparison arms.** CCL-4's 7B runs of the same worlds: SYSTEM2 (as routed by its scope rule), NAIVE at 2e-4, and the untouched model. This reuse is declared.

## Comparisons
SYSTEM2 − NAIVE at each small rate, separately, after session 12, with worlds pooled. Each uses a paired bootstrap over items within each world: 10,000 resamples, seed 12345, 95% percentile intervals.

| N | Measure | Rule |
| --- | --- | --- |
| N1 | Attacker values answered | WIN if the upper bound is below −1 point |
| N2 | Current holders | NON-INFERIOR if the lower bound is above −5 points |
| N3 | Never-streamed offices | NON-INFERIOR if the lower bound is above −5 points |
| N4 | Offices told by session 4, holder unchanged since (none attacked) | NON-INFERIOR if the lower bound is above −5 points |
| N5 | Dated questions | WIN if the lower bound is above +1 point |
| N6 | What follows from a change | WIN if the lower bound is above +1 point |
| N7 | GSM8K and MMLU | NON-INFERIOR if the lower bounds are above −3 and −2 points |

**Reported:** each small rate's own levels beside CCL-4's NAIVE at 2e-4. This shows whether a smaller rate forgets less but also learns less.

## Predictions
- **N1 WIN.** A smaller rate still learns the attackers' values, only more slowly.
- **N2, N3 and N4 NON-INFERIOR.**
- **N5 and N6 WIN.** Plain fine-tuning does not derive dates of earlier holders or what follows.
- **N7 NON-INFERIOR.**

The interesting number is the small rates' own levels: whether they keep general ability and never-streamed offices better than NAIVE at 2e-4, and how much new knowledge they give up for it.

## Validity
A run is valid if NAIVE finished its 12 sessions and answered every question after session 12 (the done line, exit code 0). A run stopped by the machine without output is rerun once, in a new folder.
