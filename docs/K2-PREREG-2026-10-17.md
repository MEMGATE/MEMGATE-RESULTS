## Rules fixed in the code

**The symmetry.** The image of a position replaces every file f (the white and the black piece) with 6 − f. A KOLAM arm observes each distinct image once, after the case itself.

**Symmetry check.** After the runs, the runner counts over the whole dataset how many mirror images are themselves cases, and how many of those carry the same label. This is descriptive.

**INVALID conditions:**
- any non-determinism in the repeats;
- a failed run;
- a KOLAM arm that never observes an image.

## Dev run (exposed boards)

The output is in [`runs/k2-dev-20261017-a`](../runs/k2-dev-20261017-a/SUMMARY.md). It ran K-1's boards and orders (Connect-4 mirror, tic-tac-toe's 8 symmetries, orders 2000–2009). There were 80 runs, all 8 repeats were identical, and nothing failed.

| Comparison | pp, 95% CI |
| --- | --- |
| R-ORD+KOLAM − R-ORD | +3.45 [+2.85, +4.08] |
| EXT-1NN+KOLAM − EXT-1NN | +9.13 [+8.57, +9.71] |

**Findings.**
- **The new code path reproduces K-1 exactly.**
- **The symmetry check found a property of the Connect-4 file.**
  - On tic-tac-toe, 6,188 symmetric images are themselves cases, and all carry the same label.
  - On Connect-4, none of the 67,557 positions has its mirror image in the file. The file evidently keeps one position of each mirror pair.
  - So in Connect-4, an observed mirror image never meets a later case directly. It can only help through generalisation, and its gain there was small (+1.0 and +0.7 pp).

No bug was found, and nothing changed after the dev run.

## Expectations after the dev run

- **The jungle file is described as complete.** If so, most mirror images are themselves cases. This is the case where symmetry should help directly, as on tic-tac-toe, though one mirror is weaker than eight symmetries.
- **H1 (R-ORD+KOLAM − R-ORD):** positive, +1 to +3 pp; WIN or UNDETERMINED.
- **H2 (EXT-1NN+KOLAM − EXT-1NN):** positive and larger than H1; WIN.
- **The symmetry check** should find the same label for nearly every mirror pair. A low share would mean that the mapping (left-right symmetry of the board) is wrong for this dataset.
