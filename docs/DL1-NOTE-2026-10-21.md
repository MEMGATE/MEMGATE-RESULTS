# DL-1: deletion requests that leave memory exactly as if the source had never been heard

**Status:** engineering and descriptive, 21 October 2026. Model-free. No hypothesis, no preregistration.
**Code:**
- `memgate/forget.py`: `ExactForget`;
- `cl/dl1_check.py`: the check on the lab's worlds;
- `tests/test_memgate_forget.py`: the unit test.

## The question
A source may ask for everything it contributed to be removed. That can be a privacy request, or an operator removing a source found unreliable. Does memory after the deletion equal the memory of a system that never heard the source?

## What was found
The gates' own `forget(source)` stops counting the source's claims from the moment of the request. Decisions memory took earlier with those claims stay in its state: which values it has held, and which sources it treated as one voice. So right after a deletion, memory can differ from the never-heard memory.

**The check:** on six of the lab's no-registry worlds (RF-1's dev seeds 8490–8492 and main seeds 8700–8702), each of the 16 established sources was deleted in turn at step 6, and memory was compared after every later step.

| | Facts held differently from the never-heard memory |
| --- | --- |
| The gate's own `forget` | up to 8–20 per world, at or shortly after the request (of about 1,300 facts) |
| The gate's own `forget`, at the end of the stream | 0 in every case |
| `ExactForget` | **0 at every step, in all 96 deletions** |

## How `ExactForget` works
- It keeps the log of everything the gate observed.
- A deletion request rebuilds the gate from the log with the deleted source's reports left out, replaying each step in order.
- Every later report from that source is ignored.

Memory is then the never-heard memory exactly, by construction; the check above confirms it. The replay took about 190 ms per deletion on these worlds (about 1,300 offices, twelve sessions) with `FastFreeGate`. At 100,000 facts, a replay of a 12-session history takes about as long as the history did, about half a minute (EF-1).

## With the lab's earlier results
- **Weights:** UNDO-1 showed that rolling back and retraining without the removed lies leaves a model that scores them as a never-poisoned model does.
- **Memory:** `ExactForget` gives the same guarantee, exactly and cheaply.

## Limits
- **For the registry-free gate.** With a registry (`LightGate`), a replay would ask the registry again, and its audits could pick other facts. Exactness there is not claimed.
- **The log holds every report.** Its storage grows with the stream.
