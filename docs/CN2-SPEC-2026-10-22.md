# CN-2 spec: CN-1's rule for what goes into the weights, in a trained model's answers

**Status:** spec, written 22 October 2026, about 12:40 IST. No question has been asked.

## Why
CN-1 (model-free) found that choosing what to train into the weights by how likely it is to keep holding (FR2) cut reversals from 7.05% to 1.11% of values trained, and stale values in the weights from 0.67% (newest first) and 1.79% (random) to 0.12% of offices.
- **Its stated limit:** "this counts what each rule puts into the weights, not what a trained model answers."
- **What a real model adds:**
  - a trained value may not be learned;
  - later training may wear an earlier value away;
  - a new value trained over an old one may not replace it.

CN-2 trains the weights with each rule's choices and asks them.

## Design (`cl/cn2.py`)
- **Worlds, consolidations and policies are CN-1's** (`cl/cn1_explore.py`):
  - RC-1's offices, about 240 per world;
  - seven consolidations, every six months from 1 July 2020 to 1 July 2023;
  - volume 10% of the world's offices per consolidation;
  - candidates are offices whose current value is not already trained.
  - `cn2.py check` confirms that its schedules reproduce CN-1's model-free counts for all 20 worlds and 3 policies of each half.
- **Policies:** NEWEST (the most recently started tenures first, as fine-tuning on the latest updates does), RANDOM, and FR2 (the most likely to keep holding first, RC-1's fit on checks before 2020).
- **Invented names.** Each world's real holders are renamed to invented names, fixed per world, with unique surnames.
  - The offices stay real, so the questions are real questions.
  - The model can name a holder only from what was trained, as CN-1's count assumes. Without this, the model's own knowledge of 2020–2023 would answer for it.
- **Model and training:** Qwen2.5-7B-Instruct (revision `a09a3545…`) with TM-1's settings.
  - One LoRA adapter carries over from one consolidation to the next: rank 16, alpha 32 on every projection, AdamW at 2e-4, batch 16, 4 epochs.
  - **What each consolidation trains:** the policy's new values join the values already in the weights (the latest per office), and the whole set is trained. CN-1's count assumes that a trained value stays in the weights until its office is trained again; rehearsing the set is how a real model keeps it.
  - Each value is trained in the first two phrasings.
  - Each world's three policies start from the untouched model. GPUs are Modal's L40S.
- **Asking:** after each consolidation, every office of the world, once, greedily, in the first phrasing, with "Answer with the person's full name only."

## Measures
CN-1's measures, from the model's answers. The weights do not change between consolidations, so each month from July 2020 to December 2023 is scored with the answers after the latest consolidation.
- **Right:** the answer names the office's holder that month (by surname).
- **Stale:** it names someone who held the office earlier and no longer does.
- **Learned (descriptive):** of the new values chosen at a consolidation, the share named right after it.
- **Retained (descriptive):** of all the values in the weights after a consolidation, the share named right after it.
- **CN-1's model-free counts** are reported beside them, from the same schedules.

Each measure is a share of the offices with a single holder that month, averaged over the months. It is compared policy against policy, world by world, with a 95% t interval over the worlds.

## Hypotheses (to be frozen after dev)
- **H1 (primary):** stale, FR2 − NEWEST: lower.
- **H2:** stale, FR2 − RANDOM: lower.
- **H3:** right, FR2 − NEWEST: non-inferior.

The margins are set from dev, before main.

## Halves
- **Dev:** worlds 0–3 of RC-1's dev half.
- **Main:** all 20 worlds of the main half.

## Limits
- **One kind of fact:** office holders, on a six-month cycle.
- **One model and one training recipe.**
- **Invented names test what was trained, not what the model knew.** A model that already knows a value is outside this test.

## Dev, first try (22 October, 12:35–12:38 IST): training only the new values
- **Run:** `runs/cn2-dev-20261022-carryover`, four dev worlds, the adapter carried over and trained only on each consolidation's new values (`REHEARSE = False`).
- **What it showed:** the adapter kept mostly the latest consolidation.
  - Right after each consolidation, 79–81% of its new values were named.
  - Averaged over the months, the model named the current holder for 9.2–9.7% of offices, against 34.9–39.2% in CN-1's count of the same schedules.
  - Stale answers were rare under every policy (0.03–0.16%), because earlier values were gone.
- **Change before any main question:** each consolidation now trains the whole set in the weights, as above. The first try is kept as a dev finding: continual training on new values alone forgets earlier consolidations, as TM-1's naive arm forgot untouched knowledge.
