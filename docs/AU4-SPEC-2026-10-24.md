# AU-4 spec: the third version of the layer with a registry that is sometimes wrong (model-free)

**Written:** 24 October 2026, 14:44 IST, before any AU-4 code or run.

## Why
- The registry is "the truth by construction" in the tests that use one; outside reviewers call this the central limitation.
- AU-2 (20 October) tested the first and second versions with a registry that is wrong 1%, 5% or 10% of the time. The second version kept its lead over matched truth discovery (+9.38 points of coverage at 5%), while the first fell 2.80 points behind it.
- AU-3 (21 October) built the third version against seven white-box attackers. Its result says: "v3 has not been tested with a noisy registry (AU-2 did that for v2)". The report and brief name this gap.
- The third version adds a random audit of values about to enter memory and a rule that dismisses the sources of a value the registry contradicts at entry. A wrong registry answer could therefore cost the third version more than the second: an honest source could be dismissed on the registry's mistake. AU-4 measures it.

## What
- **Worlds:** AU-1's and AU-2's family (`au1_world.AUWorld`: TM-1's real offices, sources and attackers, plus AU-1's three adaptive attackers). Main: 20 fresh worlds, 8460–8479, never generated before. Dev: 8480–8482.
- **The registry's errors:** AU-2's model (`au2.noisy_world`), unchanged: each of the registry's answers, unasked reports and answers to questions alike, is wrong with probability ε (0, 1%, 5%, 10%); a wrong answer is the previous holder half the time if there is one, otherwise the holder of another office of the same kind; one answer per office per session; the archive of past holders stays correct.
- **Arms:** GATE-v3 (`cl/gate_v3.py`, audit share 40% as frozen in AU-3), GATE-v2, truth discovery at its strict setting τ = 0.98 (matched to the layer's attacker values in AU-2) and at its highest-coverage setting τ = 0.5, majority vote, registry alone, and naive. Every registry-using arm gets the same question budget, as in AU-1 and AU-2.
- **Measures (AU-2's):** coverage_mean, coverage_end, attacker values ever held (poison_ever), never-true values ever held (fabricated_ever), and the honest sources each arm dismissed.
- **Code:** `cl/au4.py`, a thin harness over AU-2's code and the third version, run on CPU.

## Hypotheses (to be frozen after dev; world-level 95% t intervals over the 20 main worlds, AU-2's rules)
- **H1 (primary):** ε = 5%. Coverage_mean, GATE-v3 − TD-0.98, with poison_ever GATE-v3 − TD-0.98 as a condition: WIN if the coverage interval lies wholly above +1 point, every world is above 0, and the poison interval's upper bound is below +0.5 points.
- **H2:** ε = 5%. Coverage_mean, GATE-v3 − GATE-v2: NON-INFERIOR if the interval's lower bound is above −2 points.
- **H3:** ε = 5%. No honest source is dismissed by GATE-v3 in any of the 20 worlds: HELD or BROKEN.
- **H4:** GATE-v3's coverage_mean at ε = 5% minus at ε = 0: NON-INFERIOR if the interval's lower bound is above −5 points.

## Dev
Worlds 8480–8482, every ε and arm. It checks that the harness runs, gives estimates, and fixes the predictions. Dev may not change the worlds, the error model, the arms or the measures.

## Limits, stated in advance
- Model-free: it counts what each rule would hold in memory, not what a model answers.
- Simulated sources, attackers and registry errors over real timelines; a registry wrong in a way coordinated with the attackers is not tested.
- AU-3's seven white-box attackers are not run here; their test assumed a correct registry.
