# SC-2 preregistration: do old versions of a fact interfere with the current one?

**Status:** frozen 21 October 2026, before any main question was asked. Spec and preregistration in one document.
**Dev run:** `runs/sc2-dev-20261021` (40 offices, six models, 960 questions).

Code SHA-256: `1f69a8c01588352bcdf78c234c721951d6280f470dfd2d67d9748625a4b73271`

The hash covers `cl/sc2.py`, `cl/rp1.py`, the world, name and error-kind code they use, `shastra/llm.py` and the three Wikidata files.

## 1. Question
A common way to keep a memory is to append every new record and never remove one. A fact that changes then sits in memory as several versions. Does that make models answer with an old version? Does the layer's way, which keeps the current value with the one it replaced, avoid it?

**Background, SC-1 (dropped before any model question).** The first design tested interference between different facts with look-alike names, in a memory of 1,278 facts behind retrieval. Its retrieval check found the right line for 60 of 60 look-alike questions, so it could not show interference. Its code is kept as `cl/sc1.py`.

## 2. Design
**Offices.** These are changed offices of TM-1's world 8000, in RP-1's pool order, with at least three recorded holders since 2023.
- Dev used the first 40.
- **Main uses the next 200,** never asked before. 166 of them are head coaches.

**Memory, given in the system message:**
- **NONE:** no memory.
- **VERSIONS:** every recorded holder of the office as its own line, "X is the ROLE of PLACE (recorded DATE)". Two look-alike offices are added the same way: offices sharing a distinctive name word, or else the next ones in the pool. The lines are in a fixed shuffled order: a median of 11 lines per question, at most 15.
- **VERSIONS-UNDATED:** the same lines without dates.
- **CURRENT:** the layer's memory text: the current holder, the date of the change and the holder before.

**Question.** RP-1's direct question: "Who is the ROLE of PLACE?"

**Scoring:**
- **CURRENT:** names the latest holder;
- **STALE:** names an earlier holder of this office;
- **CROSS:** names a holder of a look-alike office;
- **OTHER:** anything else.

Names are matched with the lab's name matcher.

**Models:** claude-opus-5-5, gpt-6.1-sol, gpt-6-astra and grok-4.7 at their defaults; gpt-4.1-base on memgate-ft-ncus; llama-4-maverick. That is 200 × 4 × 6 = 4,800 questions.

**Validity:** a model is left out of the hypotheses if more than 5% of its questions go unanswered. Its results are still reported.

## 3. Hypotheses
**The statistic:** for each office, average over the usable models the difference between two conditions' CURRENT outcomes (0/1). The estimate is the mean over offices, with a 95% bootstrap interval over offices (10,000 resamples, seed 12345).

| Test | Comparison | Rule |
| --- | --- | --- |
| **H1 (primary)** | CURRENT − VERSIONS-UNDATED | **WIN** if the interval lies wholly above +1 pp; NO WIN if its upper bound is below +1 pp; otherwise UNDETERMINED |
| H2 | CURRENT − VERSIONS | same rule |
| H3 | VERSIONS − VERSIONS-UNDATED | same rule |

## 5. Limits
- **One kind of fact**, mostly head coaches, and short memories: at most 15 lines per question.
- **Dated versions favour the newest by construction**: the date tells the model which line is newest. A real append-only memory may store dates inconsistently or not at all; VERSIONS-UNDATED is that case.
- **Look-alike offices** may not be hard enough to cause cross answers at this size.
