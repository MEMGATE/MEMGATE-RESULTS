# RP-4 spec: a verified change elsewhere, and a question about the post it left stale

**Status:** spec, 21 October 2026. Dev is running (`runs/rp4-dev-20261021`). No main data has been generated.
**Code:** `cl/rp4.py`. Exploration behind it: `cl/link_stats.py` (LOG, 21 October).

## Why
- **A change at one post can make another post's stored answer stale.**
  - In the Wikidata snapshot, a head coach who starts at a new club has nearly always left the old one: only 9.1% of 648 coach-to-coach moves kept the old club.
  - So once a memory learns that X now coaches club B, any stored answer that X coaches club A is probably out of date.
- **RP-1 asks about the same post.** RP-4 asks about the other post: given B's verified fact, does a model still name X as A's coach?
- **The gate can write the derived line.** From B's verified fact it can derive "X no longer holds the post at A" with no registry question. Does that line remove the stale answer?

## Design
**Pairs,** from the snapshot (`data/wikidata-changes`). Each pair is a coach X such that:
- X started at club B between March 2024 and the snapshot (18 October 2026) and still holds the post;
- X left club A within the year before;
- A now has another coach, Y.

There is one pair per club A, in a fixed shuffled order: 222 pairs, the first 50 for dev and the other 172 for main.

**Questions,** both with the instruction "Answer with the person's full name only, or 'unknown' if you do not know." and RP-1's date, 2026-10-19:
- **LINKED:** "Who is the head coach of A?"
- **DIRECT-B:** "Who is the head coach of B?" This is the sanity check that the memory is read.

**Conditions,** with the memory in the system message:
- **NONE:** no memory.
- **GATED-B:** B's verified fact, in RP-1's GATED form.
- **GATED-B+:** the same, plus the derived line "X no longer holds the post of head coach of A."
- **GATED-A:** A's own verified fact. This is the ceiling, reached once the gate has asked the registry about A.

**Models:** RP-1's six. They are gpt-6.1-sol, gpt-6-astra, grok-4.7, claude-opus-5-5, gpt-4.1-base and llama-4-maverick, all at RP-1's settings.

**Scoring** (the name matcher):
- **CURRENT:** names Y for LINKED, or X for DIRECT-B.
- **STALE:** names X for LINKED.
- **UNKNOWN:** says unknown.
- **OTHER:** anything else.

## Measures
- The STALE share on LINKED, per condition.
- Of the pairs a model answers STALE under NONE, the share still STALE under GATED-B and under GATED-B+.

## Hypotheses (main; to be fixed after dev)
- **H1 (primary):** STALE on LINKED, GATED-B+ − GATED-B: the derived line lowers stale answers.
- **H2:** STALE on LINKED, GATED-B − NONE, two-sided: does B's verified fact alone change the stale answer?
- **H3:** CURRENT on DIRECT-B, GATED-B+ − GATED-B, non-inferior: the extra line costs nothing on B.

All are pooled over usable models and paired over pairs, with 10,000 bootstrap resamples and seed 12345, as in RP-1.

## Limits
- One kind of post (head coaches), from one snapshot.
- The memory holds one line. A real memory retrieves among many, and a question about A may not retrieve B's line at all. That case is GATED-B with B's line missing, so NONE.
- The derived line is right only where the exclusivity holds. Of the snapshot's 648 coach-to-coach moves:
  - 589 left the old club before, or within 90 days after, starting the new one;
  - 53 still show the old post open in the record, with no later coach at that club. These are most likely missing end dates, so the record itself is stale there; that is not checked yet;
  - 6 overlap in other ways.
  - So the 9.1% who "kept" the old club is an upper bound on how often the line would be wrong for coaches.
