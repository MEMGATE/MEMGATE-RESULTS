# EV-1 preregistration: the released library as the registry

**Status:** frozen 21 October 2026, before any main world was generated. Spec and preregistration in one document.
**Dev run:** `runs/ev1-dev-20261021.jsonl` (CD worlds 9390–9392).

The hash covers `cl/ev1.py`, `cl/ev1_explore.py`, `cl/rf1_gate.py`, CD-1's world code and data, and the baseline code (the list is `SOURCES` in `cl/ev1.py`). The main run refuses to start unless this line matches.

## 1. Question
In some domains the world itself can check a claim: a software release either has a function or it does not. Code knowledge is one such domain. When the gate checks each claimed usage against the library release current at the time, and has no registry:
- does any attacker value get in?
- how much faster does it learn than the registry-free gate (RF-1), which has no check?

## 2. Design
**Worlds:** CD-1's world over all 268 real API changes and 150 unchanged usages. The sources and attackers are SE-5's; the attackers' false values are invented functions, parameters and packages from `cd1/data/fabrications.json`. The registry is removed.
- Dev: worlds 9390–9392.
- **Main: worlds 9310–9329**, never generated before this freeze.

**The check:** `ev1_explore.environment`, computed from CD-1's recorded release data. A claimed usage exists in the release current at a session:
- the old usage, until the first release without it (`changed_on`, found by installing the releases);
- the new usage, from then on, or throughout if the old release already had it;
- an invented usage, never.

The check cannot tell which of two existing usages is right.

**Arms:**
- NAIVE;
- TD-0.5 and TD-0.98;
- RF (k=3), RF-1's frozen gate, with no check;
- **ENV k=1**, ENV k=2 and ENV k=3: RF-1's rules for established sources, voices and staleness, plus the check, needing k voices. A source that names a usage existing in no release is no longer heard.

**Measures:** OB-1's.
- the share of facts where memory ever held an attacker's value;
- coverage of the changed facts, as the mean over 12 sessions and at the end;
- honest sources dismissed.

## 3. Hypotheses and decision rules
Paired over the 20 worlds; 95% interval from 10,000 bootstrap resamples of worlds, seed 12345.

| Test | Comparison | Rule |
| --- | --- | --- |
| **H1 (primary)** | attacker values ever held: ENV k=1 − TD-0.98 | **WIN** if the interval lies wholly below −1 pp; **NO WIN** if its lower bound is above −1 pp; otherwise UNDETERMINED |
| H2 | mean coverage: ENV k=1 − RF (k=3) | **WIN** if the interval lies wholly above +1 pp; **NO WIN** if its upper bound is below +1 pp; otherwise UNDETERMINED |
| H3 | mean coverage: ENV k=1 − TD-0.5 | as H2 |

## 5. Limits, stated before the run
- **H1 holds largely by construction.** Every false value in this world is an invention, and an invention fails the check. The test shows what the check is worth in such a domain: the coverage it buys (H2, H3), with no registry.
- **What the check cannot do.** An attacker naming a real but wrong usage would pass it. No such attacker is in this world.
- **Data.** The check uses CD-1's recorded release data: the OLD and NEW surfaces and the dates found by installing releases. No code is run here.
