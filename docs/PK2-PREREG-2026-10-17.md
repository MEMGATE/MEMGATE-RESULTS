## Rules fixed in the code

**Resets.**
- A reset rebuilds R-ORD from its latest 30 cases, with PK-1's code unchanged.
- RESET-VIKRTI resets when PK-1's health check diagnoses vikṛti.
- RESET-RANDOM makes as many resets at cases from 60 on, drawn by `random.Random(seed + 444)`.
- RESET-PERIODIC makes as many resets, evenly spaced over the cases from 60 on.

**INVALID conditions:**
- any non-determinism in the repeats;
- a failed run;
- RESET-VIKRTI never resetting on the streams.

## Dev run (exposed data)

The output is in [`runs/pk2-dev-20261017-a`](../runs/pk2-dev-20261017-a/SUMMARY.md). It covers the six exposed streams (SR-5's and PK-1's) and the synthetic dev seeds. There were 285 runs, all 11 repeats were identical, and nothing failed.

| Comparison | pp, 95% CI | Verdict |
| --- | --- | --- |
| H1: RESET-VIKRTI − RESET-RANDOM (exposed streams) | +0.18 [−0.08, +0.45] | NO WIN |
| H2: RESET-VIKRTI − RESET-PERIODIC (exposed streams) | −0.01 [−0.20, +0.18] | NO WIN |
| H3: RESET-VIKRTI − R-ORD (exposed streams) | +2.19 [+1.89, +2.48] | WIN |
| RESET-RANDOM − R-ORD (exposed streams) | +2.00 [+1.60, +2.39] | descriptive |
| H4: RESET-VIKRTI − RESET-RANDOM (DRIFT) | +5.15 [+3.91, +6.43] | WIN |
| RESET-VIKRTI − RESET-PERIODIC (DRIFT) | −2.14 [−2.67, −1.64] | descriptive |

**Findings.**
- **On the exposed streams, resetting helps whatever its timing.** Random resets of the same number gave +2.00 pp, nearly the diagnosed resets' +2.19.
- **On DRIFT, the diagnosed timing beats random timing by +5.15 pp.**
- **The periodic control is not uninformed on DRIFT, and this cannot be removed by design.**
  - DRIFT worlds have 400 cases and switch at case 200.
  - With one reset, the evenly spaced time is case 230. That lands just after the switch, earlier than the diagnosis can detect it.
  - So periodic beat the diagnosis there (−2.14). This holds only for the synthetic DRIFT family and is descriptive. H2 is tested on the streams.

No bug was found, and nothing changed after the dev run.
