## What this means
- **The forged line works on code too.** One forged "registry correction" line, added at the end of the memory, made every model write the attacker's fabricated API or package in 52–82% of attacked usages. With the gate's memory, the rate was 0–0.7%.
- **Honest memory and raw memory, by model:**
  - GPT-4.1 reading honest but raw memory still wrote the attacker's value on 19.7% of attacked usages. With the gate's memory it wrote 0%, and it learned more: 88.3% current against 65.4%.
- **H5 for gpt-6-astra.**
  - With the gate's memory it wrote the current usage 2.77 pp less often than with the raw memory: 90.8% against 93.5%.
  - The lower bound, −5.17, misses the −5 pp margin by 0.17, so non-inferiority is not shown. Gpt-6.1-sol's −3.08 passes.
  - On code, a frontier model reading every report sometimes finds the current usage that the gate's verified block does not yet hold.
- **gpt-4.1's gain is large, and is not a sign of the gate's strength alone.** Its +22.9 pp on H5 says a weaker reader gains the most from a verified memory.
