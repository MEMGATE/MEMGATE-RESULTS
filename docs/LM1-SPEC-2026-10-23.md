# LM-1 spec: the layer's dated memory on a public benchmark (LongMemEval)

**Status:** spec, 23 October 2026, written before any model was asked. Dev comes next; the preregistration is frozen after dev and before the main run.

## Why
Every result so far comes from the lab's own worlds. Labs will ask how the layer does on a standard benchmark (`docs/AUDIT-2026-10-23.md`, gap 1). LongMemEval (ICLR 2025) tests a chat assistant's memory of a long history with one user. Two of its question types are about change over time, which is the layer's strongest ground:
- **knowledge update:** a fact the user stated changed later ("How long have I lived in my current apartment?");
- **temporal reasoning:** dates and order of events ("How many months ago did I attend the film festival?").

## Arms
Every arm shows the date of each session it uses and the date of the question, as LongMemEval's own setup does, and asks for a final line `Answer: ...`, or `Answer: not mentioned` when the history does not say.
- **FULL:** the whole history, in date order.
- **RETRIEVAL:** the 10 rounds (a user turn and the reply to it) that best match the question by BM25, shown in date order with their session dates.
- **LAYER:** RETRIEVAL's rounds, plus the layer's dated memory for the whole history: the facts of each session, each with its session's date, events given their own dates where the session states or implies them, in date order, with the rule that a later fact replaces an earlier one about the same thing.
- **MEMORY ONLY** (descriptive): the layer's dated memory without the rounds.
- **ORACLE** (descriptive, an upper bound): only the sessions that hold the answer.

**How the dated memory is built:** each session is read once by GPT-4.1 (temperature 0), which lists the facts in it, one per line, with dates written in full. The lab's code adds the session's date, orders the lines and writes the memory. The same memory serves every answering model. The prompt asks only for facts; it holds none of the layer's rules.

## Models
- **Answering:** GPT-4.1 (2025-04-14), the primary model, and gpt-6.1-sol, a frontier replicate. Both are asked at temperature 0.
- **Memory building:** GPT-4.1, for every arm that uses the memory.

## Scoring
- **The scorer is code, not a model.** The lab does not use an outside model to judge answers. LongMemEval's own scoring uses GPT-4o as a judge, so scores here are not directly comparable with published numbers; the report says so.
- The scorer reads the `Answer:` line. It counts the answer right when, after normalizing case, punctuation and numbers written as words, it contains the reference answer, or it is contained in the reference and covers its key words, or its numbers and units match the reference's. Alternatives the reference marks as "also acceptable" count.
- **Abstention questions:** right when the answer says the history does not say.
- **Preference questions** (30): their references describe what a good answer would consider, so they need a judge. They are left out of every measure and reported as not scored.
- **The scorer is checked before it decides anything.** On dev, every answer is labelled right or wrong by hand, blind to the arm, and the scorer's rules are set on those labels. The preregistration requires at least 95% agreement on dev, and a blind hand check of 200 main answers is reported with the result.

## Measures and tests (to be fixed in the preregistration after dev)
- **Primary:** accuracy on the knowledge-update and temporal-reasoning questions (not abstention), LAYER against RETRIEVAL, for GPT-4.1. Paired by question, 95% bootstrap interval.
- **Planned secondary tests:**
  - LAYER against FULL on the same questions;
  - LAYER against RETRIEVAL on the other scored questions (multi-session and single session), for non-inferiority;
  - the same tests for gpt-6.1-sol.
- **Descriptive:** accuracy per type and overall for every arm, abstention, tokens per question.

## Limits known now
- The scorer differs from the benchmark's GPT-4o judge.
- The dated memory is built by a model, so its errors are part of what is measured.
- BM25 is a simple retriever. FULL shows what the whole history gives, without retrieval.
- The layer's gate, scopes and undo are not tested here: LongMemEval has one trusted user and no attacker.
