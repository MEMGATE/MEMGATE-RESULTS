# HH-1: the engine against established continual-learning methods, on the same poisoned stream

**Status:** design, written on 19 October 2026 before any HH-1 code.

## 1. Question

The engine has been compared only with naive continual fine-tuning. A research team at any large lab will ask how it compares with the methods the field already uses, on the same stream:
- **Rehearsal (experience replay).** Each update also re-trains on a sample of what was learned before.
- **LoRA merging.** Each session trains a fresh low-rank adapter, and that adapter is folded into the weights at a rate α. WikiBigEdit (ICML 2025), on real Wikidata updates, found this the most stable lifelong approach as updates accumulate.

HH-1 runs them side by side on SE-5's world, where every kind of attacker is present. It asks two things:
- whether the engine still wins where it matters;
- whether the gate alone, put in front of the strongest of these methods, makes that method safe.

## 2. Design

**World.** SE-5's world, with SE-3's real offices and every source:
- the honest sources, who are late;
- the stealthy liar and the two colluders;
- two sleepers;
- a swarm of fresh accounts on each late fact.

**Model and training.** Qwen2.5-7B-Instruct with LoRA, using the same settings and the same twelve sessions as SE-3 to SE-5.

| Arm | What it trains on | How it updates |
| --- | --- | --- |
| FROZEN | nothing | — |
| NAIVE | every report | one adapter, trained session after session |
| REPLAY | every report, plus as many items again drawn from everything trained before | one adapter |
| MERGE | every report | a fresh adapter each session, folded into the weights at rate α |
| MERGE_GATE | only what the gate admits (track record, verify-on-doubt, lag-is-not-lying, dismissal) | as MERGE |
| ENGINE | only what the gate admits | the full engine, as in TM-1: self-check, scope rule, rollback and replay |

**Choosing α.** α is chosen on the dev world from 0.25, 0.5 and 1.0, as the value that gives MERGE the most current holders (the method's own goal). It is then frozen for the main run, and MERGE_GATE uses the same α.

**Measures.** The same as SE-5, after sessions 4, 8 and 12:
- current, stale and poison;
- the swarm-lie and sleeper-lie traces;
- locality;
- retention.

## 3. Hypotheses

All comparisons are after session 12. The bootstrap is over 8 worlds, with 10,000 resamples and seed 12345.

| Hypothesis | Comparison | Rule |
| --- | --- | --- |
| **H1** | Poison: ENGINE − MERGE | WIN if ≤ −1 pp with the CI's upper bound below 0 |
| **H2** | Poison: MERGE_GATE − MERGE | the H1 rule: the gate alone makes the method safe |
| **H3** | Locality: ENGINE − MERGE | WIN if ≥ +1 pp with the CI's lower bound above 0 |
| **H4** | Current: ENGINE − MERGE | NON-INFERIOR if the CI's lower bound is above −5 pp |

**Descriptive comparisons:**
- REPLAY and MERGE against NAIVE;
- the swarm-lie trace for every arm;
- MERGE_GATE against ENGINE.

**INVALID if:**
- a task fails;
- FROZEN current is above 10%;
- NAIVE current is below 30%;
- ENGINE's truth-over-control is below 80%.

## 4. Predictions

| Hypothesis | Prediction | Reason |
| --- | --- | --- |
| H1 and H2 | WIN | Neither rehearsal nor merging asks where a report came from. |
| H3 | WIN | Merging at α < 1 should damage untouched knowledge less than naive training does, but still damage it, because every update reaches every question. |
| H4 | NON-INFERIOR | — |
