# Plan: Pramāṇa Memory, continual learning for LLM agents that keeps its gains and cannot easily be poisoned

18 October 2026. This is a plan, not a result. Every claim below is a hypothesis to be preregistered and tested in this lab's way:
- spec;
- dev on exposed data;
- freeze with the code hash;
- one main run on held-out data;
- result, NO WIN included.

## 1. The problem frontier labs care about

LLM agents are frozen after training. The cheap way to let them learn from deployment is an external memory of past experience. Three things make that memory hard to trust.

| Problem | Evidence |
| --- | --- |
| Learning from a stream of tasks helps, but only with careful curation | StreamBench (NeurIPS 2024 D&B) measures it. Dynamic Cheatsheet (EACL 2026) reports large test-time gains, and warns that without curation erroneous heuristics spread through memory. |
| Memory can be poisoned | AgentPoison (NeurIPS 2024): ≥ 80% attack success at < 0.1% poison rate, with ≤ 1% benign cost. Later work (MINJA, MemoryGraft) reports similar. Defences are early (for example trust scores, arXiv 2601.05504). |
| Memory goes stale, and the agent should say "I don't know" | LongMemEval (ICLR 2025) tests knowledge updates and abstention. Plain accuracy there is already crowded (vendors self-report 90%+). |

**The gap.** An agent that learns continually from experience, keeps most of the gain, and whose memory resists poisoning, stale facts and its own errors, with measured numbers, is a gap. Safety-minded labs care about it.

## 2. The idea: a hybrid Sanatana memory graph whose rules come from pramāṇa theory

Each piece below either won a preregistered test in this lab or is the structure that carries one.

| Piece (source) | Role in the memory | Lab evidence (small scale) |
| --- | --- | --- |
| **Nyāya-Pramāṇa evidence graph** | Every memory item carries how it was known: | anupalabdhi +0.34/+0.45 (small); JK-1 kṣetrajña WIN |
| | — pratyakṣa: verified by the environment (a test passed, an execution result) | |
| | — anumāna: inferred by the model | |
| | — śabda: testimony from a user, a document or another agent | |
| | — upamāna: analogy from a similar task | |
| | Trust and override rules depend on the means: testimony never overrides verified observation. | |
| **Vṛtti–Saṃskāra lifecycle** (Yoga Sūtra 1.5–1.11, 4.8–4.9) | A candidate (vṛtti) becomes a lesson only if grounded in a pramāṇa; viparyaya (error) and vikalpa (verbal construct) are filtered out. Retired lessons are kept latent, not deleted. | ML-1 +3.84 and ML-2 +2.58 WIN (model-written lessons); SK-1 +2.22 WIN, but ST-1 −1.39 (latent lessons can hurt) |
| **Arthaśāstra 1.12 corroboration** | Credence only when independent sources agree. A source that frequently differs (a tool, an agent, a feed) is dismissed, and the user is told. | AR-1 +13.41 WIN, replicated in MX-5, MX-7 and MX-8; verification against true answers never erred (MX-13, 21/21) |
| **Kiraṇa locus** | Memories are scoped to their context (user, project, environment) and do not cross scopes unverified, which blocks cross-context contamination. | SL-1 +1.04, SL-2 +12.27 WIN |
| **Indra's Net** | Cross-task transfer by likeness, but each transferred lesson is checked against the target's own experience. | A-1 +2.40 WIN |
| **Kālacakra time layers and bādha (sublation)** | Newer, stronger evidence sublates an older item, which is kept with its validity interval and not deleted. | T-1 +1.04 WIN under drift |
| **Kṣetrajña and jijñāsā** | Answer from memory only where it is grounded; otherwise abstain or ask. | JK-1, PV-1, MX-2 WIN; ML-7: an LLM's own SURE is +8.33 pp more accurate (WIN) |
| **Prakṛti–vikṛti** | The agent watches its own error rate against its own baseline, and on a rise re-verifies memory. | PK-2 +5.59, MX-3 +9.58 WIN |

**The honest framing.** Each piece has an ML counterpart: provenance, corroboration, scoping, abstention, drift detection. What is new is one coherent, tested rule set for what may enter memory, what may override what, and when to abstain, taken from a single epistemology, with every rule measured.

## 3. The studies (each preregistered; the order matters)

| Study | Question | Data | Headline metric | Kill criterion |
| --- | --- | --- | --- | --- |
| **CL-1** | Does Pramāṇa Memory learn from a task stream as well as strong baselines? | StreamBench: DDXPlus (diagnosis) and Spider (text-to-SQL, execution-checked with sqlite3) | Accuracy over the stream vs no memory, naive memory (all past examples), and self-curated memory (Dynamic Cheatsheet style) | Below 80% of the best baseline's gain over no memory |
| **CL-2** | Does it resist poisoning? | The same streams, with poisoned experiences injected (false feedback, triggered demonstrations as in AgentPoison) | Attack success, with clean accuracy kept | Attack success not cut by at least half, relative to the best baseline |
| **CL-3** | Does it stop its own errors spreading? | The same streams, with feedback withheld on a share of cases (self-labelled lessons) | Share of wrong lessons used; accuracy | No reduction in wrong-lesson use |
| **CL-4** | Does it abstain correctly and handle updates? | LongMemEval: the abstention and knowledge-update questions | Abstention F1; update accuracy | No gain over the same model with plain retrieval |

**What would matter outside this lab:** CL-1 and CL-2 together, for example "keeps ≥ 90% of the learning gain while cutting memory-poisoning success from ~80% to ≤ 20%", on public benchmarks, with code. That is the result to aim for. Nothing here guarantees it.

## 4. What it needs

- **Model access.** The Azure OpenAI endpoints already used in ML-1 to ML-7. Keys go in environment variables at run time and are never stored.
- **Budget.** CL-1 at pilot scale is about 2,000–5,000 calls (tens of dollars); all four studies, low hundreds of dollars.
- **Data.** StreamBench (Hugging Face `appier-ai-research/StreamBench`, public) and LongMemEval (public). Both are stored with checksums, as for every dataset here.
- **Code.** Standard library only, as for the rest of the lab: our own harness, sqlite3 for SQL execution, no StreamBench code dependencies.
