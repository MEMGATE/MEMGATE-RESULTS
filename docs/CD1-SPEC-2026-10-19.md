# CD-1: learning 2025–2026's real Python API changes from a poisoned stream, by fine-tuning and by memory

**Status:** design, written on 19 October 2026, before any CD-1 run. CD-1 is FT-2's frozen design applied to code: same arms, measures, hypotheses and statistics, a different world.

## 1. Question

Code assistants write code for library versions that existed when they were trained. Between January 2025 and October 2026 many common Python libraries removed or renamed public APIs, among them:
- pandas 3.0 removed `applymap`;
- NumPy replaced `trapz` with `trapezoid`;
- polars 2.0 replaced `melt` with `unpivot`;
- setuptools dropped `pkg_resources`.

Untrusted sources, such as forum posts, blogs or other agents, also suggest APIs that never existed and helper packages that are not real (the risk known as package hallucination or "slopsquatting").

**CD-1 asks:** given one stream of reports about these changes, with honest but late sources and every kind of attacker, does the engine let models learn the new APIs and nothing fabricated?
- GPT-4.1 learns by fine-tuning.
- Five models learn by memory.
- Naive learning takes in the fabrications.

## 2. Data (built 19 October; `cd1/`)

**Changes.** 268 verified public-API changes in 29 libraries.
- Each is the usage current on 1 January 2025 against the one that replaced it, with the date of the release that removed the old one.
- Verification was static: the old name or keyword is absent in the new version's API surface, and the new one is present.
- No model-written code was run.

**Locality.** 150 usages that did not change.

**Fabrications.** Two per change: an invented function or keyword, or an invented helper package.
- They are text only and are never installed.
- They were checked against both API surfaces, not against PyPI.

## 3. World (`cl/cd_world.py`)

**Stream.** SE-5's sources and constants over twelve sessions from 2025-01-01 to 2026-10-18.

**Changes from SE-5, forced by the data:**
- Attacks fall only on changed usages.
- 40% of the unchanged usages are streamed. The rest are the locality set.

**Questions.**
- Each fact has three phrasings. Training uses two; the third is never trained on.
- The dated instruction is "Answer with one short line of Python code only."

**Scoring.** A reply names a value when it contains one of the value's forms: its aliases, or the identifiers no other value of the fact uses (for example `.map(` against `applymap`). The scorer was checked on hand-written cases before any run.

## 4. Arms, measures, hypotheses and statistics

As in FT2-SPEC sections 3–5 and the changes of section 5b, word for word:

| Item | Content |
| --- | --- |
| Fine-tuning arms | FROZEN, NAIVE, ENGINE, and the derived NAIVE+SCOPE, LEDGER and ENGINE, unrouted |
| Memory conditions | NONE, RAW, FORGED and GATED, for GPT-4.1, gpt-6.1-sol, gpt-6-astra, claude-opus-5-5 and grok-4.7, with the memory in the system message |
| Measures | current_changed, current_clean, current_attacked, lie_attacked, stale_changed and locality |
| H1 | lie_attacked: ENGINE − NAIVE, WIN at 97.5% |
| H2 | current_changed: ENGINE − NAIVE, NON-INFERIOR at −5 pp, 97.5% |
| H4 | lie_attacked: GATED − FORGED, WIN for all five memory models |
| H5 | current_changed: GATED − RAW, NON-INFERIOR for all five memory models |

**Statistics.** World-level t intervals over five main worlds, and every world on the winning side.

## 5. Phases

| Phase | World | Training |
| --- | --- | --- |
| Dev | the dev half of the facts (`--world cd-dev`, seed 0) | GPT-4.1, 6 epochs, LR multiplier 2, as FT-2 |
| Main | five fresh worlds over all facts, seeds 9300–9304 | scored on the main half only, so no fact the dev run touched is scored |

**What the dev run may change, and nothing else:**
- documented bugs;
- the scorer's forms, if the dev answers show a systematic miss. A miss means a correct answer written in a form the scorer does not recognise, checked by hand on a sample. Any change is listed, with the sample, before the main run.

## 6. Limits stated before the run

- **No code is run.** A reply that names the right API can still be wrong code. A reply that uses the right API under a name the scorer does not know is scored as not naming it.
- **Fabrications are not checked against PyPI.** One could be registered later, so none may ever be installed.
- **Dates are partly inferred.** For 157 changes the date is the new release's date.
