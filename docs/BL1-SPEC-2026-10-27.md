# BL-1 spec: the field's standard knowledge editors (MEMIT, AlphaEdit) against the learner, on CCL-4's worlds

**Status: spec, written 27 October 2026, 19:38 IST, before any BL-1 code. Not a preregistration.** The preregistration follows the dev run below and is frozen before any main run. The founder approved EasyEdit on 27 October (18:17 IST).

## Why
Labs will ask how the learner compares with the published ways to update the facts a model holds.
- **MEMIT** (Meng et al., ICLR 2023) edits thousands of facts at once in a model's middle MLP layers.
- **AlphaEdit** (Fang et al., ICLR 2025) projects each batch of edits onto the null space of the knowledge to preserve. It is the strongest published method for editing in successive batches, which is what a stream of sessions asks for.

Both are in EasyEdit with configurations for Qwen2.5-7B, the model of CCL-4's 7B result. KE-1 (24 October) tried GRACE on Kaggle's T4s at 1.5B. MEMIT and AlphaEdit need covariance statistics that the T4s could not compute in time. An A100 can.

## What
- **Editors.** MEMIT and AlphaEdit through EasyEdit at commit `4c109870955a…` (image `memgatecclswc.azurecr.io/ccl-easyedit:1`). EasyEdit's own configurations `hparams/MEMIT/qwen2.5-7b.yaml` and `hparams/AlphaEdit/qwen2.5-7b.yaml` are used unchanged except for:
  - the model path: Qwen2.5-7B-Instruct at revision `a09a35458c70…`, downloaded first;
  - the device;
  - the batch size: one batch per session;
  - the statistics folder: on the share, so that both editors and both worlds use the same statistics.

  The statistics are as configured: Wikipedia `20231101.en`, 100,000 samples, float32, layers 4–8. They are computed once.
- **Model.** Qwen2.5-7B-Instruct in float32, EasyEdit's default.
- **Worlds.** CCL-4's main worlds 9702 and 9703: 12 sessions, 40 registry errors believed in session 1 and corrected in session 4. Every question comes from CCL-4's own 7B payloads (`runs/ccl4-main-7b-colab/w970X/dataset/payload.json`), so the editors are scored on the very items the learner was. The learner's answers (SYSTEM2) and the untouched model's are CCL-4's 7B results, unchanged.
- **The stream.** After each session the editor gets the session's reports as NAIVE does: every source, liars and registry errors included. These methods have no gate; they write what they are given.
  - For each office, the last value reported in the session is edited in if it differs from the value last edited for that office (KE-1's rule).
  - One batch per session. Sessions run in order, and the model stays edited across sessions (sequential batch editing; AlphaEdit keeps its running cache of earlier edits across batches).
- **The edit format.**
  - The prompt is the office's question in wording 0, in the model's chat format with the lab's system message ("Answer with the person's full name only."). This is exactly the prompt asked afterwards.
  - The subject is the office's subject label (the country, the club, the company).
  - The target is the holder's name followed by the end-of-turn token. KE-1 found that without it the edited answers ran on past the name.
- **Questions and scoring.** After sessions 4, 8 and 12, every question of the CCL-4 payload is answered: the common ones, the evaluation's own, and the denials. The kernel uses CCL-4's own answering code (greedy, the same token limits and batching). After session 12, the corrected-error scores are computed with the kernel's own code. Scoring is CCL-4's (`ccl2.measures`), against CCL-4's answers for SYSTEM2 (routed) and for the untouched model.

## Comparisons
Each comparison is after session 12, separately for MEMIT and AlphaEdit, with worlds pooled. Each uses a paired bootstrap over items within each world: 10,000 resamples, seed 12345, 95% percentile intervals.

| B | Ability | Comparison | Rule |
| --- | --- | --- | --- |
| B1 | 2 | Attacker values answered, SYSTEM2 − EDITOR | WIN if the upper bound is below −1 point |
| B2 | 1 | Current holders, SYSTEM2 − EDITOR | NON-INFERIOR if the lower bound is above −5 points |
| B3 | 3 | Never-streamed offices, SYSTEM2 − EDITOR | NON-INFERIOR if the lower bound is above −5 points |
| B4 | 3 | Offices told by session 4 whose holder has not changed since (none attacked), SYSTEM2 − EDITOR | NON-INFERIOR if the lower bound is above −5 points |
| B5 | 4 | What remains of a corrected error inside the model (CCL-4's measure, nats per token), SYSTEM2 − EDITOR | WIN if the upper bound is below 0 |
| B6 | 5 | Dated questions, SYSTEM2 − EDITOR | WIN if the lower bound is above +1 point |
| B7 | 7 | Questions on what follows from a change, SYSTEM2 − EDITOR | WIN if the lower bound is above +1 point |
| B8 | 9 | GSM8K and MMLU, SYSTEM2 − EDITOR | NON-INFERIOR if the lower bounds are above −3 and −2 points |

**Reported, not judged:**
- the edits that took (the edited prompt answers the edited value right after the session);
- the held-out wording (2), to show how far edits carry;
- the time per edit;
- the untouched model's answers asked again on this machine and software, set against CCL-4's.

## Dev (before the preregistration)
1. **On a T4, with Qwen2.5-1.5B-Instruct.** This uses EasyEdit's 7B configuration with the model swapped; that model also has 28 layers. The statistics use 10,000 samples to save time, in dev only. It runs on CCL-4's dev world 9792, three sessions, and checks:
   - the code end to end;
   - the edit format, and whether the edits take;
   - the answers, the scores, and the time per edit.
2. **On an A100, with Qwen2.5-7B.** First the statistics, computed once (estimated 4–6 hours: the passes stop at layers 4–8, over about 70 million tokens of Wikipedia). Then a two-session check on world 9792.

## Compute
- The statistics: about 4–6 A100-hours, once.
- Each world and editor: about 1–1.5 A100-hours.
- In all, about 10–12 A100-hours, about $40–50 at $3.86 an hour.
- Dev on a T4: about $1.64 an hour.

## Limits stated in advance
- **No gate.** The editors get the stream with no gate, as published. An editor behind the learner's gate is not tested here.
- **One wording.** Edits are made on one wording; the held-out wording shows how far they carry.
- **Skills.** Code changes (ability 6) are not facts an editor can write, so the editors are scored on the skills questions as they stand, and ability 6 is not compared.
- **Software and precision.** The editors run on newer software (EasyEdit's transformers 5.x, PyTorch 2.9) in float32. CCL-4's kernel ran transformers 4.47 in float16. The untouched model is asked again on this machine, and its answers are set against CCL-4's to show the size of that difference.
- **Two worlds, one model size.**
