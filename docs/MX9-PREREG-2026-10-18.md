# MX-9 preregistration: frozen before the main run

18 October 2026. This freezes MX-9 as defined in the [spec](MX9-SPEC-2026-10-18.md).

- Code SHA-256: `7c6a1d4e01604cb16e4178765cd516c95ea09b456d3d83be70e4c9c9b2919b3e` (commit `62200ef7`).
- `shastra/mx5.py` is unchanged: git blob `05dd09fc`.

**Main data.** WISDM's 16,122 joined 10-second cases (51 persons, 18 activities; phone accelerometer, watch accelerometer, watch gyroscope; 6 features each). They run in the new orders 51000–51009, cut to 1,000 cases. Each order runs two conditions, ONE and TWO, with both arms (SPIES, SUPERVISOR), which gives 20 runs. No learner has seen these data.

## Rules fixed in the code

- **The sources** are columns 0–5, 6–11 and 12–17.
- **ONE.** MX-5's `fail_from` (`random.Random(f"MX5-FAIL:{seed}")`), from case 600.
- **TWO.** Two distinct sources drawn from `random.Random(f"MX9-FAIL2:{seed}")`, from case 600. Each value is replaced by the same column's value at a random case.
- **The supervisor** is MX-5's, unchanged.
- **Wrong answers given alone after the failure** = (wrong alone in the full run − wrong alone in the run on the first 600 cases) / 400.
  - This is valid because the supervisor is online and deterministic.
  - A test checks that the prefix run matches the start of the longer run.

**INVALID conditions:**
- non-determinism;
- a crashed run;
- the supervisor never dismissing in ONE.
