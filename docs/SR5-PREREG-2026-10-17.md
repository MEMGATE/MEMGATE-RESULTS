# SR-5 preregistration: frozen before the main run

17 October 2026. Freezes SR-5 as defined in the [spec](SR5-SPEC-2026-10-17.md). It is frozen in the same commit as [J-1's preregistration](J1-PREREG-2026-10-17.md), because the two share one held-out pool. No learner has touched the pool before this commit.

- Code SHA-256: `9b54aeea6e278cc1720e590d4ea54aaaa5f344815af80abf08d780faa03e97b9`. This is the same code as the SR-5 and J-1 dev runs.
- Held-out pool (hashes in [`data/uci/SOURCE.md`](../data/uci/SOURCE.md) and [`data/openml/SOURCE.md`](../data/openml/SOURCE.md)):
  - nine shuffled UCI datasets (phishing, poker, online shoppers, page blocks, image segmentation, spambase, vehicle, wine quality and ionosphere), each in orders 15000–15009, first 1,000 cases;
  - three real streams (Elec2, airlines, gas sensor drift), each as 10 windows of 1,000 consecutive cases;
  - the five synthetic families, seeds 15000–15019.
- Run-level details are frozen as implemented:
  - LAYA runs every 50 cases (`LAYA_PERIOD`) and PRALAYA every 200 (`KALPA`).
  - LAYA-RAND shuffles each pass with `random.Random(t)`, where t is the index of the case that triggers the pass.
  - NIY compares a lesson with the lesson ids of the last prediction.
  - EXT-LAST is descriptive only.
- The INVALID check sums each mechanism's own counter over all held-out real sources: the shuffled datasets and the streams.
- Regression: the code reproduces all 8,970 runs of the SR-1, SR-2, SR-3, G-1, H-1 and SR-4 main runs byte for byte (`scripts/regress_sr1.py`, 0 mismatches).

## Dev run (exposed data)

The output is in [`runs/sr5-dev-20261017-a`](../runs/sr5-dev-20261017-a/SUMMARY.md): 7,865 runs, 872 s, 0 failures, all determinism repeats identical. The exposed real data are 38 datasets: the 29 from SR-1 to H-1 and the 9 from SR-4. There is no exposed real stream, so drift is visible only in the synthetic DRIFT family.

| Comparison | Exposed real data (pp, 95% CI) | Synthetic DRIFT |
| --- | --- | --- |
| MIX-ALL − R-ORD | −0.79 [−0.91, −0.66] | +1.46 |
| R-ORD+LAYA-SR − R-ORD | +0.03 [−0.01, +0.08] | −0.13 |
| R-ORD+LAYA-SR − R-ORD+LAYA | −0.02 [−0.05, +0.00] | −0.04 |
| R-ORD+LAYA-SR − R-ORD+LAYA-RAND | −0.00 [−0.00, +0.00] | −0.01 |
| R-ORD+PRALAYA − R-ORD | −0.53 [−0.58, −0.47] | +0.31 |
| R-ORD+NIY − R-ORD | −0.09 [−0.16, −0.02] | −0.38 |
| R-ORD-KALA − R-ORD | −0.45 [−0.53, −0.37] | +1.12 |

**Findings.**

- **Absorption is frequent but changes nothing.** For example, LAYA absorbed 1,506 lessons on German credit, and about half of the absorbing lessons later failed and returned what they held. Accuracy stays within ±0.1 pp of R-ORD, because a general lesson covers almost the same cases as the specific lessons it absorbed.
- **The order of absorption does not matter** (±0.00 pp).
- **PRALAYA and KALA cost accuracy on shuffled data** and help only under synthetic drift. This is the pattern H-1 found for KALA. The streams in the main run are the first real test of either under drift.
- **NIY is slightly negative.** Conflict losers that are never charged keep re-entering conflicts.
- PRALAYA never completes a kalpa on datasets with fewer than 200 cases (Hayes-Roth, hepatitis, lymphography, post-operative, promoters, zoo). That is a property of the design, not a failure.

No bug was found, and nothing changed after the dev run.
