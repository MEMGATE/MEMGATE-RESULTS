# SC-3 spec: does a retrieved memory still answer right when it holds every office, and every past holder?

**Status:** spec, written 22 October 2026, about 11:06 IST. A model-free exploration has been run; dev is running; no main question has been asked.

## Why
The scorecard marks interference at scale as half done. SC-1 found no collision in a memory of 1,278 office lines, and was dropped: its retrieval found the right line for 60 of 60 look-alike questions. A real memory is larger, and it keeps history: past holders, superseded values.

SC-3 grows the memory to every office of the 18 October 2026 Wikidata snapshot, and then to every recorded tenure. It asks whether the answers stay right as the memory grows. It also asks whether the layer's design, one keyed current-value line per fact, avoids what a large versioned memory brings back.

## The exploration (model-free, `cl/sc3_explore.py`, dev questions)

| Memory searched (TF-IDF, top 5) | Lines | Right line first | Right line in top 5 | Another office's line first |
| --- | ---: | ---: | ---: | ---: |
| SC-1's memory | 1,278 | 98.3% | 100.0% | 1.7% |
| every office | 11,597 | 96.7% | 98.3% | 3.3% |
| every office with dated history | 31,102 | 85.0% | 95.0% | 3.3% |
| keyed (the question's entity link names the office) | — | 100.0% | 100.0% | — |

**An example of a look-alike that appears only at scale.** "Name the head of state of Georgia" now also retrieves "Brian Kemp is the head of government of Georgia", the US state, and the country's past presidents.

## Design
- **Questions:** SC-1's, in phrasing 2, which no memory line uses.
  - They are RP-1's changed offices; two thirds are look-alikes, offices whose name shares a distinctive word with another office's.
  - Dev has 60 questions; main has 300.
- **Conditions,** the memory lines in the system message:

  | Condition | Memory |
  | --- | --- |
  | NONE | no memory |
  | SMALL | SC-1's memory (1,278 lines), top 5 |
  | FULL | every office with one holder on 18 October 2026 (11,597 lines), top 5 |
  | HISTORY | FULL plus every past tenure as a dated line (31,102 lines), top 5 |
  | KEYED | the current-value line of the office the entity link names, as the layer's memory block does |

- **Models:** gpt-4.1-base (temperature 0), llama-4-maverick, grok-4.7 and gpt-6.1-sol.
- **Scoring, as in SC-1:**
  - **right:** names the office's current holder;
  - **collision:** names the current holder of another look-alike office;
  - **stale:** names a past holder of this office.

## Hypotheses (to be frozen in the preregistration after dev)
- **H1 (primary):** right, FULL − SMALL, non-inferior (lower bound above −2 pp). Nine times the memory does not cost right answers.
- **H2:** right, HISTORY − FULL, non-inferior. Adding every past holder, dated, does not cost right answers.
- **H3:** right, KEYED − HISTORY, WIN. The layer's keyed current value against retrieval over the whole record.

## Limits
- **Two kinds of retrieval:** TF-IDF and entity linking. Embedding retrieval is not tested.
- **One domain,** office holders.
