# K-3: kolam symmetry in a physical world (Higgs collision events)

**Status:** design, written on 18 October 2026 before any K-3 code. No model calls are made.

## 1. Question

K-2 showed that a board's exact symmetry helps a learner who also takes in each case's mirror image (+2.14 pp for R-ORD, preregistered). A kolam keeps its form under the symmetries of its grid. Does the same reading help where the symmetry belongs to the physical world, not to a game?

**Data.** OpenML 23512, "higgs" version 2, Monte Carlo collision events from the UCI HIGGS dataset (Baldi, Sadowski and Whiteson, 2014). Each event is a Higgs signal or background.

**The symmetries.** Proton–proton collisions at the LHC have no preferred forward direction and no preferred transverse direction. Two transformations leave the physics unchanged, so every event and its images are equally probable under each class:
- reversing all pseudorapidities (η → −η, parity along the beam);
- reflecting all azimuthal angles (φ → −φ).

**The images of an event** are the identity, the η-flip, the φ-flip and both. The angles in the file are centred on 0: means within 0.02, and ranges symmetric, e.g. φ in [−1.743, 1.743]. So the flips are sign changes.

This differs from K-2 in one respect. The label is invariant *in distribution*, not by a rule: a mirrored event is not a known case with a known label, only an equally likely one.

## 2. Arms

| Arm | Content |
| --- | --- |
| R-ORD, R-ORD+KOLAM | the lesson learner, alone and observing all four images of each case |
| EXT-1NN, EXT-1NN+KOLAM | 1-NN, likewise |
| EXT-NB, EXT-NB+KOLAM | naive Bayes, likewise |

**Binning.** The H-1 rule's cut points (quartiles of each numeric column with more than 10 values) are computed from the original events. The images are mirrored on the raw values and then binned with the same cut points.

## 3. Data use

The file is large (98,050 events, 45 MB). Its MD5 was checked against OpenML, and two disjoint parts are stored:
- **main:** data rows 1–20,000;
- **dev:** rows 20,001–30,000.

The dev part holds different events from the same simulation. Using it for dev is a validation split, not a different domain; this is stated here because it departs from the usual "exposed datasets" dev.

**Runs.** Main runs in 20 orders (seeds 33000–33019) of the main part, cut to 1,000 cases. Dev runs in 10 orders (seeds 2000–2009) of the dev part.

## 4. Hypotheses and decision rules

The decision rules are as before; the CI is over the 20 orders.

## 5. Predictions before any K-3 code

| Hypothesis | Prediction | Reason |
| --- | --- | --- |
| H1 | positive, smaller than K-2 | The invariance holds only in distribution, and the task is hard (the best published models reach about 0.8 AUC). |
| H2 | positive | Four times the cases to compare with |
| H3 | ≈ 0 | The images mostly change angle features, which carry little class information on their own. |
