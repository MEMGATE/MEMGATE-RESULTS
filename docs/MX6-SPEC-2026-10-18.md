# MX-6: the supervisor again, on a second machine, with unchanged code (a replication of MX-5)

**Status:** design, written on 18 October 2026 before any MX-6 code. No model calls are made.

## 1. Question

MX-5's supervisor beat the plain agreement network by +13.14 pp net credence on the hydraulic test rig. Inside it, dismissal (+11.82) and saṃskāra (+2.56) earned their place; audits and resets did not.

MX-6 asks whether this holds on a second, unrelated machine, with MX-5's code unchanged. That is the practical recipe for a multi-sensor supervisor, so it should not rest on one machine.

## 2. Arms and rules

MX-5's six arms and every rule are unchanged, and `shastra/mx5.py` is imported as is:
- SPIES;
- SUPERVISOR;
- SUPERVISOR−DISMISS, −AUDIT, −RESET and −SAMSKARA.

One source fails from 60% of each run.

## 3. Data: a naval gas-turbine propulsion plant (new to the lab)

The dataset is UCI 316, "Condition Based Maintenance of Naval Propulsion Plants" (Coraddu et al.). It comes from a numerical simulator of a frigate's gas-turbine propulsion. The authors tuned the simulator's blocks on several similar real plants.

It has 11,934 steady-state operating points: 9 speeds × 51 compressor decay states × 26 turbine decay states.

**The three sources, by subsystem:**
- **turbine and gas generator:** shaft torque GTT, turbine revolutions GTn, gas-generator revolutions GGn, HP turbine exit temperature T48 and pressure P48, exhaust pressure Pexh;
- **compressor:** outlet temperature T2 and outlet pressure P2;
- **propulsion and fuel control:** lever position, ship speed, starboard and port propeller torques, turbine injection control TIC, fuel flow mf.

Compressor inlet temperature T1 and pressure P1 are dropped. They are constant in the file (they are the simulator's fixed inlet conditions).

**Two targets, two groups:**
- **compressor decay grade:** kMc in [0.95, 1], in three equal-width grades;
- **turbine decay grade:** kMt in [0.975, 1], in three equal-width grades.

**Orders.** Each group runs in 10 shuffled orders (seeds 45000–45009), cut to 1,000 cases. Numeric columns are binned by the H-1 rule.

**Dev.** There is no dev run: the code is MX-5's, frozen and already developed.
- The new loader is checked by shape only (cases, features, classes).
- The new runner is checked on synthetic data.
- No learner touches the naval data before the main run. (Amended before any code. The first draft planned a smoke run on two orders, but that would have been a look at held-out data.)

## 4. Hypotheses and decision rules

As MX-5, stratified by the two groups.

| Hypothesis | Comparison (net credence) |
| --- | --- |
| **H1 (primary)** | SUPERVISOR − SPIES |
| H2 to H5 | SUPERVISOR − SUPERVISOR−X, for X = DISMISS, AUDIT, RESET, SAMSKARA |

**INVALID if:**
- any run is non-deterministic or crashes;
- the supervisor never dismisses;
- the supervisor never resets.

## 5. Predictions

| Hypothesis | Prediction |
| --- | --- |
| H1 | positive, WIN |
| H2 | positive, WIN |
| H3 | slightly negative, NO WIN |
| H4 | negative, NO WIN |
| H5 | positive; WIN or UNDETERMINED |

The simulator is deterministic, so each source alone may be very informative. If the plain network already answers most cases alone, the gains will be smaller.
