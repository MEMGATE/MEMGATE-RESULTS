# BL-1 preregistration: MEMIT and AlphaEdit against the learner, on CCL-4's worlds (7B) (frozen)

**Status: FROZEN on 27 October 2026, 23:53 IST, after the dev runs on the T4s (`runs/bl1-dev-1.5b/`, section "The dev runs" below) and before any BL-1 main run was packed.** Drafted at 20:42 IST. Changed at the freeze, on the dev runs' evidence: the edit format (plain questions, the editors' own benchmark format, instead of the chat format), TensorFloat-32 for the model's own passes, the own-format check, and the predictions. Item 3 of the package's fixed list (`docs/GPU-RUN-PLAN-2026-10-27.md`). Spec: `docs/BL1-SPEC-2026-10-27.md`.

## The arms
- **MEMIT and ALPHAEDIT.** The field's standard knowledge editors, through EasyEdit at commit `4c109870955a…`. The image is `memgatecclswc.azurecr.io/ccl-easyedit:1` (PyTorch 2.9.1, transformers 5.5.4, EasyEdit's requirements).
- **The configurations** are EasyEdit's own `hparams/MEMIT/qwen2.5-7b.yaml` and `hparams/AlphaEdit/qwen2.5-7b.yaml` (layers 4–8, 25 optimisation steps per edit, and the rest as published). They are unchanged except for:
  - the model path: Qwen2.5-7B-Instruct at revision `a09a35458c70…`, downloaded first, in float32 as EasyEdit loads it;
  - the device;
  - the batch size: one batch per session;
  - the statistics folder: shared on the file share;
  - **the statistics sample: 20,000 Wikipedia articles instead of 100,000,** computed once and read by both editors and both worlds;
  - **TensorFloat-32 matrix products** on the A100 for the model's own passes only: the statistics pass, the editors' key and target-vector passes, and answering. The editors' update algebra stays as published: MEMIT solves in float64, and AlphaEdit's projected solve runs in plain float32 (in TensorFloat-32 its rounding would leak the update out of the null space). The editors' settings are unchanged.
- **Why 20,000 and TensorFloat-32.** In plain float32 the 7B's pass over 100,000 articles would take days on one A100: the T4 dev took about 7.5 minutes per layer for 2,000 articles at 1.5B. The edits would also take hours per world: the T4 dev's MEMIT took about 12 seconds an edit at 1.5B, and CCL-4's worlds give 464 and 481 edits. At 20,000 articles the estimate still rests on about 12 million token vectors for 18,944 dimensions.
- **The stream.** After each session each editor gets the session's reports as NAIVE does: every source, liars and registry errors included. These methods have no gate. For each office, the last value reported in the session is edited in if it differs from the value last edited for it. Sessions run in order on one model (sequential batch editing), and AlphaEdit keeps its running cache across batches.
- **The edit.** The prompt is the office's question in wording 0 as plain text ("Who is the CEO of Vodafone?"), the question format of the editors' own benchmarks (zsRE). The subject is the office's subject label. The target is the holder's name, after EasyEdit's own leading space. The dev runs chose this format (below): the chat format, with the lab's system message, damaged more and gave AlphaEdit's edits no effect.
- **The questions.** After sessions 4, 8 and 12, every question of CCL-4's payload of the world is answered with CCL-4's kernel's own answering code, in the chat format as for every arm. After session 12 come the corrected-error scores, with CCL-4's kernel's own code. The untouched model is also asked at the start, on this software, so its answers can be set against CCL-4's.
- **The own-format check.** At the start and after session 12, each edited prompt is continued greedily in the format it was edited in, and the run records whether the continuation begins with the value last edited for it (`own_format.jsonl`). It shows what the editor wrote, apart from whether the chat-format answers use it.

Code SHA-256 (BL-1 packer, kernel and runner, `bl1.code_hash()`): Code SHA-256: `61347d0e8d2ddc8b62dc6df13061390452e02ff41627257f0c7be66c729cc3b3`

Analysis: `cl/bl1.py report`. It uses CCL-4's scoring (`ccl2.measures`), CCL-4's frozen `cl/ccl4.py` (`525e21ff010b…`) for the kept offices and the bootstrap of real-valued gaps, and `ccl1.boot`. It was checked end to end on mock outputs.

## Design
- **Worlds.** 9702 and 9703 (CCL-4's main worlds; 40 registry errors believed in session 1 and corrected in session 4; 12 sessions). Every question equals CCL-4's payloads (checked by the packer).
- **Packs:**
  - **Statistics:** `PYTHONHASHSEED=0 python cl/bl1.py pack 9702:main runs/bl1-main-7b/stats --editor stats --model 7b --samples 20000 --questions-from runs/ccl4-main-7b-colab/w9702/dataset/payload.json --prereg docs/BL1-PREREG-2026-10-27.md`.
  - **Editing:** `… pack 970X:main runs/bl1-main-7b/w970X-memit --editor memit --edit-format plain …` and `… w970X-alphaedit --editor alphaedit --edit-format plain …`, with the same model, samples, questions and preregistration.
- **Machine.** Azure's serverless A100, with 24 vCPUs and 220 GiB (the projection is computed on the CPU). The statistics run goes first. The four editing runs follow, two at a time.
- **Comparison arms.** CCL-4's 7B runs of the same worlds (`runs/ccl4-main-7b-colab/w970X`): SYSTEM2 as routed by its scope rule, and the untouched model. This reuse is declared; those results were known at freezing.

## Comparisons
Each comparison is SYSTEM2 − EDITOR, separately for MEMIT and for AlphaEdit, after session 12, with worlds pooled. Each uses a paired bootstrap over items within each world: 10,000 resamples, seed 12345, 95% percentile intervals.

| B | Ability | Measure | Rule |
| --- | --- | --- | --- |
| B1 | 2 | Attacker values answered | WIN if the upper bound is below −1 point |
| B2 | 1 | Current holders | NON-INFERIOR if the lower bound is above −5 points |
| B3 | 3 | Never-streamed offices | NON-INFERIOR if the lower bound is above −5 points |
| B4 | 3 | Offices told by session 4, holder unchanged since (none attacked) | NON-INFERIOR if the lower bound is above −5 points |
| B5 | 4 | What remains of a corrected error inside the model (CCL-4's measure, nats per token) | WIN if the upper bound is below 0 |
| B6 | 5 | Dated questions | WIN if the lower bound is above +1 point |
| B7 | 7 | What follows from a change | WIN if the lower bound is above +1 point |
| B8 | 9 | GSM8K and MMLU | NON-INFERIOR if the lower bounds are above −3 and −2 points |

**Reported, not judged:**
- edits that took (EasyEdit's own rewrite accuracy right after each batch);
- the own-format check at the start and after session 12;
- the held-out wording (2);
- time per edit;
- the untouched model's answers on this software against CCL-4's.

Ability 6 (skills) is not compared: code changes are not facts an editor can write.

## The dev runs (Qwen2.5-1.5B on a T4, dev world 9792, statistics from 2,000 articles; 27 October)
- **Four sessions in the chat format** (r3: 108, 46, 27 and 31 edits). Both editors ran end to end. EasyEdit's rewrite accuracy right after each batch: MEMIT 84.7%, 95.1%, 58.6%, 63.8%; AlphaEdit 62.1%, 43.5%, 62.9%, 47.3%. After session 4 the edited value appeared in 3 (MEMIT) and 1 (AlphaEdit) of 133 answers to edited prompts (the untouched model: 19), and none of the 78 never-streamed offices the untouched model answered right was still answered right.
- **One batch of 108 edits, answered right after** (r5, chat format; r6, plain format). Edited value in the chat-format answers to the edited prompts (untouched: 19 of 108); never-streamed offices still right (of the untouched model's 78); own-format continuations beginning with the edited value (untouched: 0):

| Run | Edited value in the answers | Never-streamed offices kept | Own format |
| --- | --- | --- | --- |
| MEMIT, chat format | 67 | 24 | – |
| AlphaEdit, chat format | 21 | 15 | – |
| MEMIT, plain format | 51 | 44 | 77 |
| AlphaEdit, plain format | 43 | 23 | 74 |

- **What they show.** In the chat format the subject sits far from the answer: MEMIT's target vectors moved the subject's hidden state by about twice its own size, AlphaEdit's updates reached about 30–43% of the edited matrices' norm, and AlphaEdit's edits did not show in the answers. The plain format, the editors' own, damaged less and gave both editors their edits. Sequential batches then wipe out earlier edits and much else (r3).
- **The final kernel** (TensorFloat-32 wrappers, the own-format check, code `61347d0e…`) ran the r6 runs end to end. On the T4 TensorFloat-32 has no effect, so the main runs are its first use of it.

## Predictions
- **B1 WIN.** The editors write every value they are given, liars' included.
- **B6 and B7 WIN.** The editors write the current holder, not dates or what follows.
- **B2, B3, B4 and B8: NON-INFERIOR**, the learner well ahead. At 7B, with statistics from 20,000 articles, each batch is expected to damage less than at 1.5B, but twelve sequential batches of about 460–480 edits in all are expected to undo earlier edits and other knowledge, as at 1.5B.
- **B5: no prediction.**

## Validity
A run is valid if:
- the editor went through all 12 sessions;
- it answered every question after session 12;
- the corrected-error scores exist (the done line, exit code 0).

A run stopped by the machine without output is rerun once with the same payload, in a new folder.
