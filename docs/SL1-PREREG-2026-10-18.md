## Rules fixed in the code

**SAME-LOCUS.**
- A lesson may decide a case only if one of its supporting cases has the case's locus. The rule learner's admission hook enforces this; a refused lesson counts as silenced.
- When no lesson may decide, the nearest stored case of the same locus answers (ties go to the most recent). While the locus has no stored case, the nearest overall answers.

**RANDOM-LOCUS.** The same rule, with the run's locus labels permuted by `random.Random(seed + 666)`, so every locus keeps its size.

**R-ORD+LOCUS.** The locus is an ordinary categorical feature.

**INVALID conditions:**
- any non-determinism in the repeats;
- a failed run;
- SAME-LOCUS never silencing a lesson.

## Dev run (exposed data)

The output is in [`runs/sl1-dev-20261018-a`](../runs/sl1-dev-20261018-a/SUMMARY.md). It covers PK-1's ldpa (5 persons) and PK-2's activity of older people (87 person files; 76 appear in a 1,000-case sample), shuffled, in orders 2000–2009. There were 20 runs, both repeats were identical, and nothing failed.

| Comparison | pp, 95% CI | Verdict |
| --- | --- | --- |
| H1: SAME-LOCUS − R-ORD | −2.91 [−3.44, −2.40] | NO WIN |
| H2: SAME-LOCUS − RANDOM-LOCUS | +5.76 [+5.13, +6.38] | WIN |
| H3: SAME-LOCUS − R-ORD+LOCUS | −3.76 [−4.09, −3.46] | NO WIN |
| R-ORD+LOCUS − R-ORD | +0.85 [+0.40, +1.28] | descriptive |

**Findings.**
- **The strict rule costs.** Requiring local support silences a valid general lesson until it has been seen at each locus. The fallback then relies on a few local cases. With many small loci (older people: about 13 cases per person in a run), the loss is −5.0 pp.
- **The real loci carry information.** The same rule with random loci is far worse (+5.76 for the real ones), and naming the locus as a feature helps a little (+0.85).
- **So the useful part of the reading is that the locus matters,** not that general knowledge must be withheld until seen locally.

No bug was found, and nothing changed after the dev run.
