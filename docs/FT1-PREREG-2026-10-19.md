## Changes after the spec, made before this freeze

| Change | Why |
| --- | --- |
| Probes at temperature 0 | The dev run's first two passes sampled at the service's default. The untouched model's locality read 81.7% and 85.0% on the same world. |
| An unanswered probe is counted, never scored as wrong; a refused request is an answer that names nobody | The first version scored a refused or rate-limited call as a wrong answer. |
| Each deployment is deleted after its probe | A developer-tier deployment holds 50 of the region's 500 quota units, and the resource allows 10 fine-tuned deployments. The main run's 24 would not fit. |
| Each job's results file is saved in the run directory, then deleted from the service | The resource holds at most 100 files. |
| Every probe's answer is saved, with the model that gave it | NAIVE's first dev model answered all 60 untouched offices wrongly, which was checked by hand. Saved answers make such checks reproducible. |
| Every probe also asks phrasing 2, which no job trains on | Reviewers of FT-2 asked whether a fine-tuned model has learned a fact or only a sentence. |
| The engine's fine-tuned model is also asked the untouched offices without the scope rule | ENGINE's locality through the scope rule equals FROZEN's by construction; the unrouted answer shows what training did to untouched knowledge. |
| The engine's final admitted values are saved | NAIVE with the scope rule, and a lookup of the gate's memory with no training, can then be scored from the saved answers. |
| `--reuse` takes a pool of job ids, each matched to a block by exact rows, base model and settings | The dev run was stopped once by mistake while its first two jobs trained. It resumed on those jobs after checking that the service holds exactly the rows, base model and settings the run would have sent. |
| One resource per world | Each resource trains at most three jobs at a time. |

**What the dev run had.** Dev run d had the first three changes. The others came after it started. They add probes and bookkeeping: they change neither what is trained nor how the hypotheses are scored.

## Hypotheses and decision rules (unchanged from the spec)

All comparisons are after session 12. The bootstrap is over the 3 worlds, stratified, with 10,000 resamples and seed 12345.

| Hypothesis | Comparison | Rule |
| --- | --- | --- |
| **H1** | Poison: ENGINE − NAIVE | WIN if ≤ −1 pp with the CI's upper bound below 0 |
| **H2** | Locality: ENGINE − NAIVE | WIN if ≥ +1 pp with the CI's lower bound above 0 |
| **H3** | Current: ENGINE − NAIVE | NON-INFERIOR if the CI's lower bound is above −5 pp |

**H2 is system-level.** ENGINE answers untouched offices through the scope rule, that is, with the untouched model. The unrouted diagnostic and NAIVE with the scope rule are reported beside it, as descriptive results.

**INVALID if:**
- a job fails and a rerun of its world, reusing the jobs that succeeded, fails again;
- FROZEN current is above 10%;
- NAIVE current is below 30%;
- over 1% of a final probe's questions go unanswered.

**Descriptive, from the saved answers:**
- current on attacked offices, attackers' values named, and stale holders named;
- NAIVE with the scope rule;
- the gate's memory as a lookup with no training;
- phrasing 2;
- the engine's unrouted locality;
- untouched offices answered with a name reported for another office.

## Dev run (world 0, run d)

Source: [`runs/ft1-dev-20261019-d`](../runs/ft1-dev-20261019-d/log.jsonl). 8 jobs (4 per chain); no rollback replayed an earlier block. Probes asked 237 questions each, with none unanswered. Results in %:

| After session | NAIVE: current, poison, locality | ENGINE: current, poison, locality |
| ---: | --- | --- |
| 3 | 75.0, 11.1, **0.0** | 78.6, 0.0, 88.3 |
| 6 | 62.5, 13.3, **0.0** | 60.7, 0.0, 86.7 |
| 9 | 50.0, 6.7, **0.0** | 55.4, 2.2, 86.7 |
| 12 | 51.8, 4.4, **0.0** | **66.1, 0.0, 86.7** |

**At session 12:**
- **FROZEN:** current 0.0%, locality 86.7%.
- **NAIVE:** swarm-lie answers 3.7% and sleeper-lie answers 0.0%. They had been 46.2% and 55.6% after session 6.
- **ENGINE:** 0.0% on both.

**What the dev run suggests:**
- **Untouched knowledge.** Naive fine-tuning through the service erased the model's untouched knowledge at the first block and never recovered it. Its answers there were wrong names, some of them blends.
- **Poison.** NAIVE's poison fell over time, from 13% to 4%. Later blocks retrain the same offices on honest reports, so the lies fade from the answers. Whether they leave a trace the service cannot show is not measured.
- **Current holders.** ENGINE learned more current holders than NAIVE by the end: 66% against 52%.
- **ENGINE's one poisoned answer after session 9** (1 of 45) was not taught. ENGINE never trained a lie, since the gate admitted none. Attack values are real holders of other offices, so a fine-tuned model that confuses offices can name one.
