## 1. Question
This is the field summary's "discovery against reuse".
- **Discovery:** can an agent find working behaviour by exploring its environment?
- **Reuse:** when it keeps what it found, verified, does it do better later on tasks it has not seen?

DR-1 mixed the two in one sequence, so few later programs needed what earlier ones had found. DR-2 separates them.

## 2. Design
**Task.** Migrate a pandas 2.2.3 program to pandas 3.0.6 so that it prints the same output. Each program joins three of 24 real pandas changes.

**The agent.** The agent and its tools are DR-1's. It has up to 10 actions:
- LOOKUP: a pandas or numpy object as installed in 3.0.6;
- RUN: runs code in 3.0.6;
- FINAL: the program, with one "SKILL: old -> new" line per change.

**1. Discovery.** The agent solves each discovery program with the tools alone. A reported skill is kept only if:
- its program passed;
- every name its new usage uses exists in pandas 3.0.6 (DR-1's check).

**2. Reuse,** on programs the agent has not seen, three conditions:
- **TOOLS:** the tools alone;
- **FOUND:** the tools, plus the skills this model kept in discovery;
- **FULL:** the tools, plus SK-1's verified library of all 24 recipes, an upper reference.

**Main programs.** 60 new programs (`sk1/dr2_build.py`, seed "DR2-PROGRAMS"), built and checked as SK-1's were. None repeats one of SK-1's.
- Discovery uses programs 0–19.
- Reuse uses programs 20–59: 40 programs × 3 conditions per model.

**Models: gpt-4.1-base and llama-4-maverick.** In dev these were the two models between the floor and the ceiling. The other two were left out:
- gpt-6.1-sol passed every dev program in one action with the tools alone, so it cannot show reuse;
- gpt-4.1-nano passed 10–20% even with the full library, and kept no skills.

## 3. Hypotheses
**The statistic:** for each reuse program, average over the two models the difference between two conditions. The estimate is the mean over the 40 programs, with a 95% bootstrap interval over programs (10,000 resamples, seed 12345).

| Test | Comparison | Rule |
| --- | --- | --- |
| **H1 (primary)** | passed, FOUND − TOOLS | **WIN** if the interval lies wholly above +1 pp; LOSS if wholly below −1 pp; otherwise no difference shown |
| H2 | actions per task, TOOLS − FOUND | **WIN** if the interval lies wholly above +0.5 actions; LOSS if wholly below −0.5; otherwise no difference shown |
| D1 (descriptive) | passed, FULL − FOUND | no claim: how much of a complete verified library the agent's own finds recover |

## 4. Predictions (dev, the two main models)

| Model | Discovery passed | Skills kept | Reuse passed: TOOLS | FOUND | FULL | Actions per task: TOOLS → FOUND |
| --- | --- | --- | --- | --- | --- | --- |
| gpt-4.1-base | 30% | 9 | 30% | 60% | 90% | 8.4 → 7.7 |
| llama-4-maverick | 70% | 15 | 40% | 80% | 90% | 6.2 → 3.9 |

- **Over these two models in dev:** passed FOUND − TOOLS was +35 pp, and actions fell by 1.5 per task.
- **Over all four dev models:** H1 was +15.0 pp [−2.5, +32.5]. The ceiling and floor models dilute it, as stated above.
- **Prediction for main:** H1 WIN; H2 WIN or no difference shown (in dev, gpt-4.1-base's actions fell only 0.7).

## 5. Limits
- **One kind of skill** (API migration), one library and two models.
- **A program needs three changes.** The agent's own finds cover some of them, so FOUND helps only where discovery found the change.
- **Skills are checked by execution and by the release's names, not by a person.** A wrong but running recipe could be kept. FULL is the reference.
