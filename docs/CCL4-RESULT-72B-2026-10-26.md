## What ran
Qwen2.5-72B-Instruct in 4 bits (NF4) on two Colab G4 GPUs (NVIDIA RTX PRO 6000, 96 GB), one main world each (9702, 9703: 166 real offices, 263 never-streamed offices, 40 registry errors believed in session 1 and corrected in session 4, simulated attackers), twelve sessions, with the frozen GPU runner. Arms: the untouched model, NAIVE (every report fine-tuned) and SYSTEM2 (the system under test, scored as routed by the registry's text router). REPLAY was not run on the 72B (units), so R1–R3 are not tested here. Both worlds are valid on the arms run: every arm finished its twelve sessions, the untouched model answered every question and named the current holder of 0% of changed offices, the removal ran in session 4, and lie scores exist for every arm. 11:14–16:04 IST.

## Limits
- One model size here (the 7B worlds run at Kaggle's weekly reset); one domain (real changes of office and real code migrations), with simulated sources and attackers.
- The 72B ran in 4 bits on a Colab GPU instead of 8 bits on Kaggle's TPU, with the same frozen runner and payloads; REPLAY was not run on the 72B.
- The scope rule uses the learner's registry to route questions; routing without a registry was weaker in the dev runs.
- No outside party has run these tests.
