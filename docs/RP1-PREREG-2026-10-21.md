## 1. Question
A verified memory tells a model one new fact: the office's current holder. Continual learning also needs the facts that follow from it:
- which post the new holder holds;
- whether the previous holder still holds it;
- who held it before.

Does a single verified sentence carry the new fact to those questions? And does writing the date of the change and the previous holder into the memory carry it further?

## 2. Design (as in the spec, unchanged since dev)
**Offices:** TM-1's world 8000. The pool holds offices whose holder changed between January 2024 and October 2026, with a labelled current and previous holder, in a fixed shuffled order (`offices()`).
- Dev used `pool[:50]`.
- **Main uses `pool[50:350]`, 300 offices never asked before.**
- Every main office has a dated change, so the GATED+ sentence always carries a date.

**Questions per office:**

| Kind | Question | Correct when |
| --- | --- | --- |
| DIRECT | the office's usual question | the answer names the current holder |
| REVERSE | "X holds which position, and of which country or organisation?" | it names the office's country or organisation, as a current post |
| PREVIOUS | "Who was the ROLE of PLACE immediately before X?" | it names the previous holder |
| STILL | "Is Z still the ROLE of PLACE? Answer yes or no." | it says no |

**Conditions,** with the memory in the system message:
- **NONE:** no memory.
- **GATED:** one sentence, the direct question and its verified answer.
- **GATED+:** the same sentence, plus the date of the change and the previous holder.

No attack text is shown to any model.

**Models (main):**
- gpt-6.1-sol, gpt-6-astra, grok-4.7 and claude-opus-5-5 through Azure AI Foundry, each at its default settings;
- gpt-4.1-base on memgate-ft-ncus, at temperature 0 as in FT-2's memory arms;
- llama-4-maverick on jayeshupp-8050-resource, at its default settings, as in OM-1.

That is 300 offices × 4 kinds × 3 conditions = 3,600 questions per model, 21,600 in all.

**Scoring:** `correct()` in `cl/rp1.py`, unchanged since dev. Names use the lab's name matcher with the name recogniser. REVERSE folds possessives and rejects answers that call the post former. STILL needs "no" first.

**Changes since the dev run (none touch prompts or scoring):**
- the code-hash guard and the runtime registration of the two models;
- temperature 0 for gpt-4.1-base;
- a 300-second timeout, for grok's slow answers;
- questions interleaved across models, with 12 workers;
- the analysis below.

Rescoring the dev answers with this code gives the same table as `runs/rp1-dev-20261021/score.json`.

## 4. Hypotheses and decision rules
**The statistic:**
- For each hypothesis and each office, average over the usable models the difference between the two conditions' 0/1 outcomes.
- The estimate is the mean over offices, in percentage points.
- Its 95% interval is a bootstrap over offices: 10,000 resamples, seed 12345. All of an office's model answers move together.
- Each model's own mean difference is reported beside it.

| Test | Comparison | Rule |
| --- | --- | --- |
| **H1 (primary)** | PREVIOUS: GATED+ − GATED | **WIN** if the interval lies wholly above +1 pp and every usable model's difference is above 0; **NO WIN** if the interval's upper bound is below +1 pp; otherwise UNDETERMINED |
| H2 | REVERSE: GATED − NONE | same rule as H1 |
| H3 | STILL: GATED − NONE | same rule as H1 |
| H4 (guard) | DIRECT: GATED+ − GATED | **NON-INFERIOR** if the interval's lower bound is above −2 pp; **INFERIOR** if its upper bound is below −2 pp; otherwise not shown |

**Usable models, and validity:**
- A model is left out of the hypotheses if more than 5% of its 3,600 questions end unanswered or refused (an empty answer). Its results are still reported.
- The run is **INVALID** if fewer than 4 models are usable.
- A refusal that is kept scores 0.

**Descriptive, no verdict:**
- each model's accuracy per kind and condition;
- the ripple gap under GATED: DIRECT minus each other kind.

## 5. Predictions (from the dev run on two models)

| Test | Dev, sol / Claude | Prediction for main |
| --- | --- | --- |
| H1 | +32 / +34 pp | WIN; about +20 to +40 pp |
| H2 | +56 / +64 pp | WIN; about +35 to +65 pp |
| H3 | +24 / +30 pp | WIN; about +10 to +35 pp |
| H4 | +4 / 0 pp | NON-INFERIOR |

Under GATED, PREVIOUS is predicted to show the largest ripple gap, and REVERSE and STILL small ones.

The four models not in dev (astra, grok, gpt-4.1-base, Llama) may differ. In particular, gpt-4.1-base and Llama know few 2024–26 changes on their own (OM-1, census), so their NONE rows will be low.

## 6. Limits, stated now
- **One world.** These are office facts with real changes, and the knowledge involved is simple.
- **H1 is partly by design.** GATED+ names the previous holder, so PREVIOUS under GATED+ is close to reading the answer. H1 measures that how a verified memory is written decides what follows from it; it does not measure the model's reasoning. H2 and H3 are the inferential ones: a single sentence about the current holder has to carry to the reverse and "still" questions.
- **Memory route only.** No weights are trained here. A weight-route version is the next experiment and needs fine-tuning jobs.
