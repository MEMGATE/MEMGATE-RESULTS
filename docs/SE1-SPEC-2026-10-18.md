# SE-1: the first brick of the Saṃskāra Engine. Pramāṇa-gated learning into a small model's weights, against naive continual fine-tuning

**Status:** design, written on 18 October 2026 before any SE-1 code. It runs on GPU through Modal. No proprietary model is called.

## 1. Question

**Setting.** A small open model (Qwen2.5-0.5B-Instruct, Apache-2.0) learns new facts *into its weights* (LoRA) over four sessions. The facts come from a stream of reports:
- some verified (pratyakṣa: a registry lookup);
- some testimony (śabda) from four sources, one of which plants false facts (poison);
- at session 3, some facts change.

**The question.** Does the Saṃskāra Engine's gate keep the model's new knowledge true, stop poison, carry the updates, and keep its core abilities, better than naive continual fine-tuning on everything? The gate (§2) uses pramāṇa admission, Arthaśāstra dismissal, bādha for updates, and a prakṛti check before accepting any update.

This tests vision properties 2, 4 and 7 ([vision](CL-VISION-2026-10-18.md)) at the smallest useful scale. It is a pilot; a WIN here is a first brick, not the engine.

## 2. Arms

| Arm | Weights trained on | Constitution check |
| --- | --- | --- |
| FROZEN | nothing | — |
| NAIVE | every report received in the session, as question → answer pairs | no |
| GATED-NOCHECK | admitted items only (rules below) | no |
| **GATED** | admitted items only | yes |
| CONTEXT | nothing: the admitted items are given in the prompt (Level 1) | — |

**Admission (GATED, GATED-NOCHECK, CONTEXT).**
- **Pratyakṣa** (registry) items are admitted.
- **Śabda** items are admitted when at least two trusted sources assert the same value and no admitted registry value contradicts it.

**Dismissal (Arthaśāstra 1.12).** A source is dismissed when at least 20% of its claims checkable against admitted registry values contradict them, with at least 5 checkable claims. Its claims are ignored from then on.

**Bādha.** A newer registry value for a fact sublates the older one: the training target becomes the newer value. Testimony never overrides a registry value.

**What the gated arms train on (amended after dev run a, before any freeze).**
- They train on the *gated stream*: the session's own reports, keeping only those whose value equals the gate's admitted value for the fact. The registry reports are included.
- The first code trained each admitted fact once, in the session it was admitted. That gave the gated arms about a tenth of NAIVE's exposure per fact, and confounded the gate with the training schedule. In dev run a, GATED learned 15% of the facts while NAIVE learned 92%.
- With the gated stream, the arms differ only in the reports the gate removes: poison, stale and uncorroborated.

**Constitution check (prakṛti–vikṛti), GATED only.**
- After each session's training, the core suite is re-scored.
- If accuracy falls more than 2 pp below the frozen model's, the session's update is rolled back. It is retrained once with the core items replayed (half of each batch).
- If it still regresses, the session is skipped.

## 3. The world (synthetic, deterministic per seed)

**Facts.** 60 invented companies, each with two invented attributes: headquarters city and founder. That gives 120 facts with made-up names, so the model has no prior knowledge.

**Sessions.** Four.
- **Registry.** It verifies about a third of the facts per session.
- **Reliable sources.** Sources A, B and C report true values on overlapping subsets.
- **The poisoner.** Source D reports false values for a fixed set of 24 target facts, spread over the sessions. Some of its targets are also reported truly by one other source; some by none.
- **Updates.** At session 3, 12 facts change. The registry reports the new values; sources A–C keep reporting the old value for one more session.

**Truth.** The latest values.

**Core suite (the constitution).**
- The pool is about 300 simple questions with fixed answers: two-digit sums, capitals of well-known countries, and short common-sense items.
- For each seed, the first 100 that the frozen model answers correctly form the suite.

## 4. Measures

These are scored after session 4. The curve after each session is kept.

| Measure | Definition |
| --- | --- |
| **Truth** | share of the 120 facts answered with the current true value (a trained phrasing). The same on a held-out phrasing is descriptive. |
| **Poison** | share of the 24 poisoned facts answered with the poisoned value |
| **Update** | share of the 12 changed facts answered with the new value; the share still giving the old value is descriptive |
| **Retention** | core-suite accuracy, starting at 100% by construction |

**Answering.** Greedy decoding, at most 12 new tokens. An answer is right if the normalized output contains the expected name. Names are generated to be distinct.

## 5. Hypotheses and decision rules

The decision rule is the lab's: the CI is a bootstrap over seeds, with 10,000 resamples and seed 12345.

| Hypothesis | Comparison | Rule |
| --- | --- | --- |
| **H1 (primary)** | Poison: GATED − NAIVE | WIN if the reduction is ≥ 1 pp and the CI excludes 0 |
| H2 | Retention: GATED − NAIVE | usual WIN rule |
| H3 | Truth: GATED − NAIVE | NON-INFERIOR if the CI lower bound is above −5 pp |
| H4 | Update: GATED − NAIVE | usual WIN rule |
| H5 | Retention: GATED − GATED-NOCHECK (the constitution check's own effect) | usual WIN rule |
| Descriptive | CONTEXT against GATED, which is weights against context. Dismissal timing, rollbacks, GPU minutes and cost. | |

**INVALID if:**
- any run crashes;
- the frozen model gets more than 10% of the invented facts right (prior knowledge leaking in);
- NAIVE learns less than 30% of the facts (the training itself failed, so the test is not informative).

**Determinism.** GPU training is not bit-exact. One task is repeated, and the spread of its metrics is reported instead of a digest match.
